## Current state

- **Environment integration:** Package re-exports `buildBacklogEnv()`, `resolveBacklogScope()`, `suggestClaimantIdentity()`, and `backlogEnvironmentSpec` from `./env.js` — already fully integrated with `@adhd/environment@0.0.2`. The dependency is declared in `package.json`.
- **Scope resolution:** Defaults to `global` scope per SPEC.md §3 requirement (one shared graph spanning every repo on the machine), with override chain: explicit option → `ADHD_BACKLOG_SCOPE` → `ADHD_ENV_SCOPE` (generic fallback) → `'global'` default.
- **Configuration model:** `BacklogConfig` is a typed interface with two nested namespaces: `db` (path + busyTimeoutMs) and `logging` (level). All config fields are expressed as dot-path FieldSpecs in `backlogEnvironmentSpec`.
- **Directories and files:** Package declares `dirs.data` (kind: data) and `files.db` (in: data, name: backlog.db). SQLite handles its own WAL/SHM files automatically.
- **Bin entry guard:** `index.ts` implements the dual-purpose entry pattern (library barrel + CLI bin). The guard checks `process.argv[1]` (resolving symlinks with `realpathSync`) against `import.meta.url` and calls `runBacklogCli()` only when executed as the entry point. Error output is `console.error(stack or message)` with `process.exitCode = 1`.
- **Logging in index.ts:** Only raw `console.error` in the entry guard; no structured logging or file persistence at this layer. The log-level config field exists but utilized elsewhere (client operations).

## Proposed `EnvironmentSpec`

```typescript
const backlogEnvironmentSpec: EnvironmentSpec<BacklogConfig> = {
  envPrefixOverride: 'ADHD_BACKLOG',
  namespaces: ['production'],
  dirs: {
    data: { kind: 'data' },
  },
  files: {
    db: { in: 'data', name: 'backlog.db' },
  },
  config: {
    'db.path': {
      type: 'string',
      env: 'ADHD_BACKLOG_DATABASE_PATH',
      description: 'SQLite backlog-graph DB path. Unset ⇒ falls back to env.files.db under the resolved scope root.',
    },
    'db.busyTimeoutMs': {
      type: 'integer',
      env: 'ADHD_BACKLOG_DATABASE_BUSY_TIMEOUT_MS',
      default: 5000,
      description: 'SQLite busy_timeout (ms) each write waits for a contended lock before retrying. Raise when scaling toward more concurrent agents writing the same global-scope store.',
      at: 'build',
    },
    'logging.level': {
      type: 'string',
      env: 'ADHD_BACKLOG_LOG_LEVEL',
      default: 'info',
      enum: ['trace', 'debug', 'info', 'warn', 'error', 'fatal', 'silent'],
      at: 'build',
    },
    'migration.phase': {
      type: 'string',
      env: 'ADHD_BACKLOG_MIGRATION_PHASE',
      default: 'not-started',
      enum: ['not-started', 'phase-1', 'phase-2', 'phase-3', 'phase-4', 'phase-5', 'complete'],
      description: 'MIGRATION.md §4.4 — a queried signal (never hardcoded prose) for whether BACKLOG.md or the tool is authoritative right now. Read via migrationStatus(ctx)/backlog migration-status. NOT yet per-repo-keyed (MIGRATION.md §9 open decision 6) — one global value.',
      at: 'build',
    },
  },
};
```

**Rationale for `at: 'build'`:**
- `db.busyTimeoutMs`, `logging.level`, `migration.phase` are read once at Environment construction (when `buildBacklogEnv()` is called) and never re-read during the process lifetime. They configure static properties (SQLite timeout, log verbosity threshold, migration state marker) that do not change reactively. Even though `logging.level` *could* support hot reload, no read site in the package re-reads it after startup, so `at:'build'` is correct.
- `db.path` defaults to `undefined`, which triggers fallback to `env.files.db` — a build-time path resolution. If explicitly set via env var, it also resolves at construction and is frozen.

## Gap detail

None. The package is fully adopted and compliant with `@adhd/environment`'s capability:
- All env var reads use the `ADHD_BACKLOG_*` prefix (guarded by `envPrefixOverride`).
- All file/directory writes route through `env.files.db` and `env.paths.data`, created via `env.ensureDirs()`.
- Config cascade is fully implemented: code defaults → `EnvironmentSpec` → system/global/project scope files → env vars.
- Scope marker detection (`.git`, `.adhd`, or `ADHD_ENV_SCOPE`) is delegated to the `Environment` base class; backlog merely defaults to `global`.

## Logging audit

- **Has logging:** Yes. Index.ts emits error logs via `console.error` in the bin entry guard.
- **Logger:** Raw `console` (Node built-in).
- **Persists log files:** No. Output is stdout/stderr only.
- **Log destination:** stdout/stderr only (console.error writes to stderr).
- **Structured:** No. Plaintext (error.stack or error.message).
- **Error handling:** Adhoc. Catches promise rejection in bin guard, logs stack or message, sets exit code to 1. No propagation beyond the process (no re-throw or logging framework integration).
- **Benefit from `env.paths.logs`:** Yes. If the package were to adopt structured logging (e.g., migrate console.error to pino/winston writing to `env.paths.logs` with kind: `logs`, share: `per-instance`), concurrent backlog instances would never collide on the log file. Currently, all instances write to stderr, which is simple but not auditable or rotatable. A persisted log file keyed by instance would be an improvement but is not required for core functionality.
