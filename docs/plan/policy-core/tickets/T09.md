## Evidence
Gates (after the last edit of this ticket):
- `npx nx run policy:lint` -> exit 0
- `npx nx run policy:typecheck` -> exit 0
- `npx nx run policy:build` -> exit 0
- `npx nx run policy:verify-dist-load` -> exit 0

Behaviour through the built bin (`node entrypoint/policy/dist/cli.js`, scratch dir, throwaway HOME, policy `gate.yaml` with `touch` allowed for `role: writer` when `argv.0` matches `^[a-z]+\.txt$`, `touch` asking for `role: reviewer`, `sh` and `echo` allowed for writer):
- `run bin:touch --spec gate.yaml --adhd-attributes @attrs-writer.json -- file.txt` -> exit 0, `file.txt` created, `policy: <path>` on stderr.
- same with no attributes (role defaults to `anon`) -> exit 3, stderr `no permission allows touch`, no file; reviewer (`ask`) -> exit 3 `requires approval (matched global:1)`, no file; writer with `BAD.TXT` (args filter) -> exit 3, no file.
- `--adhd-attributes @bad.json` holding `"not-an-object"` -> exit 2 (`attributes: ... must be a JSON object`), no file (read eagerly before anything starts); unknown `--adhd-nope` -> exit 2 (`unknown flag --adhd-nope`).
- child exit status is returned: `run bin:sh ... -- -c 'exit 7'` -> exit 7. Arguments after `--` are untouched: `run bin:echo ... -- --adhd-attributes hello` prints `--adhd-attributes hello`.
- D-06 precedence: `ADHD_POLICY_ATTRIBUTES` alone grants (exit 0); flag `reviewer` plus env `writer` -> exit 3 (flag wins, never merged).
- no `--spec` and no `workspace-policy.yaml` found -> `policy: built-in`, exit 3, nothing created (WM-11, PD-03).
- `mcp-json init --spec gate.yaml` on a `.mcp.json` with a stdio entry and a `url` entry: stdio entry becomes `{command:'adhd-policy', args:['serve','bin:node','--spec','<abs>','--','/abs/stub.js','/abs/stub.log'], env}`, remote entry `skipped: remote-entry`, `*.adhd-policy.bak` written; a second `init` -> `changed:false`, `cmp` identical; `mcp-json init --undo` and `mcp-json --undo` -> `cmp` identical to the original (exit 0); no backup -> exit 4; missing file -> exit 4.
- `serve bin:node --spec notes.yaml --adhd-attributes @attrs-writer.json -- stub.mjs stub.log` driven by a real SDK stdio client against a real stub MCP server: `tools/list` returns the upstream names `note`, `purge` unchanged with annotations; writer `note` -> upstream log shows the call, result `ok note`; writer `purge` -> `isError:true`, `no permission allows stub.purge`, upstream log has no `purge`; with no attributes both calls are `isError:true` and the upstream log is empty. SIGTERM to `serve` ends both the wrapper and the stub (no processes left).

Deviations / notes:
- Verb functions receive argv WITHOUT the verb name (`dispatchVerb` strips `argv[0]`); `IVerbDeps` gained the optional `launcher` and each verb is loaded with a dynamic `import()`, so `check` and the other admin operations never load the gateway, the policy Layer or the MCP SDK (`mount.ts` and `src/entry/*` import neither `@adhd/apigen-plugin-policy` nor the gateway: LP-05).
- `serve` takes the upstream command as `bin:<command>` with arguments after `--` (`serve bin:node --spec f -- stub.js stub.log`). The demo's `serve "bin:node stub.js stub.log"` (arguments inside the source string) is rejected by the gateway's `parseSourceSpec` (`invalid-spec`: no whitespace) per D-07, which also matches what `mcp-json init` writes; T17/T18 reconcile the demo text.
- `splitPolicyArgv` rejects ANY unknown `--flag` before the `--`, not only `--adhd-*` (a mistyped flag must not be silently ignored by a gate). `--spec` values are positional layers (global, project, local), so a single `--spec` is the `global` layer, which is also the only layer that may carry absolute paths.
- `mcp-json` also accepts `init --undo` (the demo's spelling) as well as `--undo`; `--file` defaults to `.mcp.json` in the working directory; the spec path is written absolute.
- Backup rule refinement (D-10 says "only if the backup does not exist yet"): the backup is also refreshed when no entry is wrapped yet, i.e. a fresh `init` after an `--undo`; otherwise `--undo` after an edit-then-init would restore a stale original. A repeated `init` (some entry already wrapped) never overwrites the backup.
- `serve` returns 0 on clean shutdown through `SIGINT` / `SIGTERM` (`installAbortOnSignals`, passed down by `runPolicyCli`).
- New dependencies of `@adhd/policy`: `@adhd/apigen-engine-gateway`, `@adhd/apigen-plugin-policy`, `@modelcontextprotocol/sdk` (1.29.0, the repo pin, for `StdioServerTransport`).
