## File interface specs
Root: `packages/policy/policy-core-client/src/core/`. Allowed imports: `../spec/index.js`, `@adhd/data-query-engine` (ONLY under `core/engine/`), `node:crypto` is NOT allowed (core is isomorphic-pure): the sha256 is implemented in `canonical/sha256.ts` (a ~60-line pure implementation, with NIST test vectors in Phase C). ### `core/engine/matches.ts`
```ts
import { Query } from '@adhd/data-query-engine';
import type { FilterExpression } from '../../spec/index.js';
/** True if `row` satisfies `expression` (QE-01). Never throws: an engine error returns false. Resolves `_within` and array `_contained_in` against the row first (see within.ts, walk.ts). */
export function matches(row: Readonly<Record<string, unknown>>, expression: FilterExpression): boolean;
```
Impl: `neutralizeAbsent(expression)`, then (when `_within` / array `_contained_in` appear) `rewriteOperators` with a per-row resolver that replaces those operator nodes by constants, then `new Query({ where }).where!(row)` (via `engine/query.ts`); wrap in try/catch -> false. Cache the neutralised expression and the compiled predicate (row-free expressions only) in `WeakMap`s keyed by the expression object.

### `core/engine/within.ts`
```ts
import type { FilterExpression } from '../../spec/index.js';
/** Path normalisation (D-13): collapse `.`/`..`/duplicate slashes lexically with posix semantics; no fs access; a trailing slash is dropped except for root. */
export function normalizePath(p: string, cwd?: string): string;
/** True when `value` (a string, or a list whose every element is a string) lies within some root (D-13): both sides `normalizePath`ed against `cwd`; an empty or non-array `roots` list is false. Per-row resolution: the engine's `_like` is substring-only and `_contained_in` scalar-only, so no expression-only rewrite of `_within` is possible. */
export function isWithinRoots(value: unknown, roots: unknown, cwd?: string): boolean;
/** True when the expression (recursively) contains `_within`. */
export function containsWithin(expression: FilterExpression): boolean;
```
Note: substitution (T04) runs first, so `roots` is already a concrete string array when `matches` resolves `_within`; the row value at the field path is read per row and normalised by `isWithinRoots`.

IF-01 (first step): verified. `new Query({ where }).where` is a synchronous `(row) => boolean`; no one-row view is needed (probe run on the engine before coding).

Engine facts found by probing (they drove the deviations below):
- `_like` is substring containment (`a.includes(b)`), not SQL `%`/`_` wildcards; `_contained_in` is scalar list membership (`list.includes(value)`), not subset; `_eq` compares `JSON.stringify`; `_and: []` / `_or: []` throw; `_not` is "some child is false"; a missing field makes `_ne` and `_is_null: true` true.

Deviations from the file specs:
- `rewriteWithin(expression)` (expression-only rewrite into `_or` of `_like` prefixes) cannot work: the engine's `_like` has no wildcards and a row list value (`child.read_roots`) needs "every element within". `within.ts` exports `normalizePath`, `containsWithin` and `isWithinRoots`; the row-dependent resolution of `_within` and array-valued `_contained_in` happens in `matches` through `engine/walk.ts` (`rewriteOperators`), which replaces those operator nodes with constant nodes before the engine runs. `neutralizeAbsent` uses the same walker and the same constant-false node; `_and: []` / `_or: []` fold to constants. `matches` calls `neutralizeAbsent`, then the row resolver, then the engine (`engine/query.ts` is the single place the engine is constructed).
- `SUPPORTED_OPERATORS` excludes `_period` (reads the wall clock, violating QE-08) and includes `_between` / `_nbetween`. `validateExpression` also flags a literal regex operand that does not compile.
- LY-05 as built: a project layer may not set an absolute path in `defaults[].set` or a permission `set` (`layer-violation`). The spec text "attribute names starting `shared_` may be set by global/local only" is NOT enforced, because demo S4 (B4.1) has the project layer set `shared_read_roots: []` (AP-06) and expects compile to succeed.
- Layers with schema errors, unknown names or repeated names are reported and excluded from `ordered`/`documents`, so later phases run on well-formed documents and the result still lists every issue.
- Extra internal files (not exported): `core/engine/walk.ts`, `core/engine/query.ts`, `core/attributes/kinds.ts`, `core/canonical/clone.ts`, `core/compile/hash.ts`, `core/compile/expr-walk.ts`, `core/schema/validate.ts`.
- Imports are extensionless, matching neighbouring packages.
- The compiled policy returned by `compile` is deep-frozen (same as `loadCompiled`).
- `package.json` gained `"@adhd/data-query-engine": "^2.3.10"`. `pnpm-lock.yaml` was NOT regenerated (another agent has it staged); see the deferral list in the final report.

Absent-attribute negatives in a `context` are fixed in T04 (`matchesPresent`, `falsifyAbsentFields`): a comparison on a field missing from the row is false, `_is_null` alone remains the presence test (AT-10, AT-12). `matches` itself keeps raw engine semantics, so `args` rows are unchanged.
