## Scope
Functional tests from demo Scenario 1 (B1.1-B1.4) through the client root as a consumer imports it. Negative controls recorded.

## Acceptance (Gherkin)
Library consumer, unit lane. Merged here: B1.4 (explain) into T16 @S6.4.

```gherkin
Feature: Library first - compile once, decide in process, no server

  Background:
    Given a scratch directory "<DEMO>" with real paths (work/readme.md, work/.env, work/out/notes.txt)
    And a policy document with attributes {role: name, read_roots: paths}, default role "guest", a files.read allow within read_roots, a files.* deny on ".env", and a dev-only files.write allow that forces overwrite=false

  @S1.1 @happy
  Scenario: Importing the package starts nothing
    When a script imports "@adhd/policy-core-client"
    Then the exports include compile, evaluate, explain, narrow, resolve, verify, draft and createDecider  # D-01
    And no timer, socket or child process is left running and the script ends by itself with status 0

  @S1.2 @happy
  Scenario: Allowed read and allowed write with a forced value
    Given a developer with read_roots ["<DEMO>/work"]
    When the policy is compiled and the developer reads "<DEMO>/work/readme.md"
    Then the decision effect is "allow"
    When the developer writes "<DEMO>/work/out/notes.txt"
    Then the effect is "allow" and "set" is {"overwrite": false}

  @S1.2 @negative
  Scenario: A secret path is denied even inside the developer's read root
    Given a developer with read_roots ["<DEMO>/work"]
    When they read "<DEMO>/work/.env"
    Then the effect is "deny" with denial code "explicit-deny"
    And the same call without the deny permission would have been allowed  # negative control

  @S1.3 @happy
  Scenario: Compiling is deterministic and the result is plain data
    Given a policy with no attributes block and no runtime provider
    When it is compiled twice
    Then both succeed, the serialized results are identical, and each carries a content hash and schemaVersion 1
```

Not tested (deliberately):
- B1.2 anonymous caller gets `no-match`: same outcome as S2.5 through the CLI; not repeated at library level.
- B1.4 explain: merged into T16 @S6.4 (same operation, same assertions).
- Exact export list beyond the named operations: extra exports are caught by the build gate / review (DoD 1), not a functional test.

Conventions for all test files: vitest, unit lane (`*.spec.ts`, no subprocess, no network, no sleeps), one `describe` per Gherkin Feature, test titles begin with the scenario tag (e.g. `@S2.3 ...`). Tests import ONLY what a third party can import: the package root (`@adhd/policy-core-client`), the CLI via `runPolicyCli` from `entrypoint/policy/src/wrapper/mount.ts` with `process.exitCode`/stdout captured by `helpers/capture.ts`, the Layer via its default export. Scratch files only under `tmp/policy/<test-name>/` created in `beforeEach`, removed in `afterEach`/`finally`. Negative controls are recorded in Evidence (not committed).
