**IF-12 check (first step, run before any wrapper code).** Extracting the built `policy-core-client/dist/service/api.d.ts` with `extract({sourceFile, namespace:'policy', dropFileSegment:true})`:
- `evaluate`/`check`/`explain`: `args` keeps `{type:object, additionalProperties:{}}`; `attributes` keeps `additionalProperties:{oneOf:[string, number, string[]], x-apigen-logical:'union'}`; `runtime` keeps `oneOf:[string, number]`. `narrow.request` keeps its object schema (`grant`/`only`/`attributes` as `$ref: #/definitions/Attributes` -> object of the attribute-value union). `ILayerInput.document` is `{}` (declared `unknown`). No operand was lost, so no field was changed to `unknown`.
- Two real extractor problems were found and fixed in `service/api.ts` (T05 follow-up edits, allowed by this ticket):
  1. `draft(_ctx, input)`: the extractor recognises the injected context only when the first parameter is named exactly `ctx` (`extract.ts` `hasCtx = params[0].name === 'ctx'`). `_ctx` made `draft` expose a `_ctx` input property and `hasCtx` undefined. Renamed to `ctx` (with `void ctx`).
  2. `compile`/`verify`/`resolve`/`show` declared a required `input` although every field is optional, so `adhd-policy verify` failed with `missing required key 'input'`. `input` is now optional on those four (the bodies already used `input?.`).
- Operation inputs are wrapped as `{ input: {...} }` (the client's single `input` parameter). `$ref` definitions appear in `narrow`; `buildPolicyPackage` inlines them (apigen run-mode cannot resolve `$ref`), same algorithm as `entrypoint/backlog` `dereferenceSchema`.

**Real CLI input form (D-03), for T18 to reconcile with the demo.** Commands are `adhd-policy [policy] <verb> --input '<json>'`; the leading `policy` namespace segment is optional (`prefixCommand`). `--input` takes a JSON string of the operation's input object; there are NO per-field flags (`--tool`, `--args`, `--attributes`, `--parent`, `--request`, `--operations`, `--options` do not exist) and `--input @file` is not supported (`Invalid JSON for --input`). `verify`, `compile`, `resolve`, `show` and `doctor` need no `--input`. The demo's `adhd-policy check --tool X --args '{}' --attributes '{}'` must therefore become `adhd-policy check --input '{"tool":"X","args":{},"attributes":{}}'`. Lists survive: `"read_roots":["/a"]` reached the policy as a list (`files.read` under the root allowed).

Behaviour through the built bin (`node entrypoint/policy/dist/cli.js`, demo B2.0 policy in a scratch dir, throwaway HOME):
- `verify` -> exit 0, `{"ok":true,"errors":[],...}`; a policy with an undeclared attribute and an unknown operator -> exit 2 with both errors listed (verify `ok:false` -> exit 2 through the cliPlugin `options.exitCode` hook).
- `check` allow (`files.read` inside `read_roots`) -> stdout `{"effect":"allow",...}`, exit 0.
- `check` of `<root>/.env` -> exit 3 (`permission_denied`, `denied by permission project:2`); `evaluate` of the same call -> exit 0 with `explicit-deny`, matched `["project:0","project:2"]`.
- `check` of `billing.refund` for a support role -> exit 3 (`requires approval`); `check --input '{"args":{}}'` -> exit 2 (`invalid_argument`); a policy file that does not parse -> exit 1 (`policy failed to load: <file>: ...`), never an allow.
- `resolve`, `draft` -> exit 0 with the documented JSON. `policy: <path>` is announced once on stderr (D-12).
- `adhd-policy-http` (`ADHD_POLICY_HTTP_PORT=47832`): `POST /policy/evaluate` with body `{"data":{"input":{...}}}` -> 200 decision JSON; `POST /policy/check` of a denied call -> 403 `permission_denied`. `adhd-policy-mcp` driven by a real SDK stdio client: `tools/list` returns `policy_compile,...,policy_draft` and `policy_evaluate` returns the decision as text + `structuredContent`.

Deviations / notes:
- No `bin/*.js` shim files: `entrypoint/backlog` has no `bin/` directory either; its `package.json#bin` points at the bundled `dist` entry, which carries the shebang through the vite `output.banner`. Same here (`bin` -> `./dist/{cli,mcp,http}.js`). The three entry files import `../wrapper/mount` and contain no logic (`ADHD_POLICY_HTTP_PORT` is the port setting the ticket allows).
- The artifact is a policy-local format (`formatVersion`, `extractorVersion`, `surfaceSha256` over the client's `.d.ts` surface, `operations`), not the `@adhd/apigen-plugin-ir-cache` `CachedExtractEntry`, because that package is outside this ticket's allowed imports. `readBakedIr` falls back to live extraction on any mismatch.
- `@adhd/sox-telemetry` was added to the allowed imports: the tracing plugin drops every record and warns on stderr until `initTelemetry` runs, so `wrapper/telemetry.ts` calls it once per process (`role: 'cli'` for the CLI, `'live-service'` for MCP/HTTP).
- `@adhd/apigen-base-errors` is imported for `ApiError('invalid_argument')` (HTTP non-loopback refusal, `ir-artifact` usage), as the ticket's own text requires.
- The exit-code hook maps any result shaped `{ok:false, errors:[...]}` (verify and compile reports) to 2.
- `dereferenceSchema` is copied from `entrypoint/backlog/src/server.ts` (not exported there). Two consumers now carry it; extracting it into `apigen-core-client` is a deferral for the report.
- `src/wrapper/mount.ts` and `src/entry/*` import neither `@adhd/apigen-plugin-policy` nor the gateway (LP-05); `verbs/index.ts` is the T09 seam (`dispatchVerb`), first landed as a `{handled:false}` stub so this ticket compiles on its own.
