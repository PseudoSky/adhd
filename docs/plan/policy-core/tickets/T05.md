Behavior notes: `compile`/`verify` with `input.layers` use those instead of `ctx.layers()` (no ctx.policy needed); malformed `tool` (empty / not string) -> `ApiError('invalid_argument')` before any decision (exit 2). `evaluate`: runtime values = `input.runtime`, else if `ctx.runtime` -> one `observe({scope: undefined, tool, attributes})` call, else undefined; records one `IAuditEntry` to `ctx.audit` if present (never throws if the sink throws). `doctor` checks: policy compiles, layer source readable, settings resolved, runtime provider present (informational). `draft` ignores ctx.

Deviations / notes:
- `EnvironmentSpec` accepts the spec 10.2 object unchanged: `DirKind` includes `config`, `cache`, `logs`, and `files: { in, name }` matches `entrypoint/backlog/src/env.ts` (IF-03 resolved, no delta). `buildPolicyEnv` maps `projectRoot` to the environment `cwd`.
- `yaml` is `^1.10.2` (the version the repo already installs); 1.x rejects duplicate keys by default, so no option is passed. It is imported as a default import, as `environment-builder` and `environment-cli` do.
- `ICompileResult`'s failure variant gained an optional `warnings` so `verify` can report warnings together with errors (D-05); `compile` fills it. Additive; `LAYER_ORDER` is exported from the internal core barrel for `verify`.
- `verify` returns an `IVerifyReport` with `ok: false` for a defective policy (all issues listed) and does not throw; a host maps it to exit 2 with the cli-output `options.exitCode` hook (T06). A policy file that cannot be read or parsed fails every operation with `ApiError('internal', ...)` naming the file (exit 1, FC-06).
- `draftPolicy` converts the LIKE secret patterns to anchored `_regex` (a leading `%/` also matches the bare name), because the engine's `_like` is a substring test and cannot express "ends with"; `DEFAULT_SECRET_LIKE_PATTERNS` keeps the LIKE spelling from the spec. The leading deny is omitted when there are no path arguments (an empty `_or` is invalid).
- `IFsLayerSourceOptions.cwd` is optional: without it no walk-up happens, so nothing ever consults `process.cwd()` (`createPolicyCtx` takes `ports.cwd`).
- `ctx.ts` builds its in-memory source inline so `ctx-env.ts` stays the only ctx file importing `./config`.
- `evaluate` records one audit entry whose `attributeNames` are the effective attribute names (after defaults); `explain` records none.
- `check` reports `ask` as `permission_denied` (OD-16).
