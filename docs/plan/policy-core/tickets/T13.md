## Acceptance (Gherkin)
`run bin:` with an injected fake process launcher that records whether and how the child was started; no real subprocess. Merged: B3.0 (fixture), B3.4 into @S2.2 (deny wins is already proven) and the S3.2 outline, B3.5 into @S3.2.

```gherkin
Feature: Put a policy in front of any command - run bin:

  Background:
    Given gate.yaml (dev may run "touch" with cwd inside write_roots; interns "ask"; any cwd under ".ssh" denied)
    And a fake launcher that records every start with its argv and cwd

  @S3.1 @happy
  Scenario: A developer in the write root runs the command unchanged
    Given attributes {"role":"dev","write_roots":["<DEMO>/work/out"]} passed with --adhd-attributes
    When "run bin:touch --spec gate.yaml --adhd-attributes @attrs.json -- made-by-dev.txt" runs from "<DEMO>/work/out"
    Then the launcher recorded exactly one start with argv ["made-by-dev.txt"] and cwd "<DEMO>/work/out"  # D-07
    And no --adhd-* flag reached the child
    And the exit code is the child's own exit code (0)

  @S3.2 @negative
  Scenario Outline: A refused call never starts the command
    Given <attributes>
    When the same "run" is invoked from "<cwd>"
    Then the launcher recorded no start
    And stderr gives a refusal reason and the exit code is 3  # D-04

    Examples:
      | attributes                                    | cwd                |
      | dev with write_roots [<DEMO>/work/out]        | <DEMO>/work        |
      | dev with write_roots [<DEMO>/home]            | <DEMO>/home/.ssh   |
      | no --adhd-attributes and no env source        | <DEMO>/work/out    |

  @S3.3 @edge
  Scenario: ask with nobody to answer is a refusal, and attributes are re-read per invocation
    Given the dev attributes file allows the call in "<DEMO>/work/out"
    When the file is replaced by the intern attributes and "run" is invoked again from the same place
    Then the launcher recorded no second start
    And the exit code is 3  # D-04, D-15

  @S3.6 @negative
  Scenario: Attributes that are not a JSON object refuse to start
    Given an attributes file containing the JSON string "not-an-object"
    When "run bin:touch ... --adhd-attributes @bad-attrs.json -- never.txt" runs
    Then stderr says the attributes must be a JSON object
    And the launcher recorded no start and the exit code is 2  # D-06
```

- B3.4 and B3.5: deny-beats-allow is @S2.2; empty-attributes-is-guest is @S2.5; both appear here only as rows of @S3.2 to prove the gate holds on the `run` path.

- `ADHD_POLICY_ATTRIBUTES` precedence over nothing and under the flag (D-06): not in the demo.
