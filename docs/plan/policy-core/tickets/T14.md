## Scope

## Acceptance (Gherkin)
Library level; layers passed explicitly (discovery paths are D-10 and T18). Merged: B4.2 (decisions across layers) into @S4.1 scenarios below.

```gherkin
Feature: Layers - global, then project, then local

  Background:
    Given three layers compiled in the order global, project, local as in B4.1
    And "<DEMO>/shared/guide.md" and "<DEMO>/shared/.env" exist

  @S4.1 @happy
  Scenario: The last layer that sets a value wins, and the source is reported
    When attributes are resolved for {"role":"support"}
    Then max_refund is 20 with provenance starting "local:"
    And shared_read_roots is ["<DEMO>/shared"] with provenance starting "global:"
    And the supplied role has provenance "supplied"
    When attributes are resolved for {"role":"release"}
    Then repos is ["acme/shop"] (provenance "project:") and max_refund is 0 (provenance "global:")

  @S4.1 @edge
  Scenario: An explicit empty list stops inheriting
    When attributes are resolved for {"role":"reviewer"}
    Then shared_read_roots is [] with provenance starting "project:"
    And for {"role":"dev"} it is still ["<DEMO>/shared"]

  @S4.1 @edge
  Scenario: A value the caller supplied is final
    When attributes are resolved for {"role":"support","max_refund":5}
    Then max_refund is 5 with provenance "supplied"

  @S4.1 @negative
  Scenario: A deny in a higher layer cannot be lifted by a lower one
    Given a dev with read_roots ["<DEMO>/work"]
    Then reading "<DEMO>/shared/guide.md" is allowed (global permission)
    And reading "<DEMO>/work/readme.md" is allowed (project permission)
    And reading "<DEMO>/shared/.env" is "deny" with code "explicit-deny" although the local layer allows ".env"
```

Not tested (deliberately):
- On-disk discovery of global/project/local files: not in B4.1 (layers passed explicitly); covered by D-10 reconciliation in T18.
- Permission-order effects beyond deny-wins: PM-09/PM-10 are the last scenario.
- Order sensitivity of the compile array: that is the negative control for the first scenario, recorded in Evidence, not a separate scenario.

Conventions for all test files: vitest, unit lane (`*.spec.ts`, no subprocess, no network, no sleeps), one `describe` per Gherkin Feature, test titles begin with the scenario tag (e.g. `@S2.3 ...`). Tests import ONLY what a third party can import: the package root (`@adhd/policy-core-client`), the CLI via `runPolicyCli` from `entrypoint/policy/src/wrapper/mount.ts` with `process.exitCode`/stdout captured by `helpers/capture.ts`, the Layer via its default export. Scratch files only under `tmp/policy/<test-name>/` created in `beforeEach`, removed in `afterEach`/`finally`. Negative controls are recorded in Evidence (not committed).

### Phase C: S4 layers through the apigen Layer (`packages/apigen/apigen-plugin-policy`)

Nothing is mocked. Attributes travel the way an auth layer delivers them (`call.envelope.attributes`).

Per-scenario coverage (all in `layered-decisions.spec.ts`, each title begins `@S4.1`):
- last layer wins, source decides the outcome: refund ceiling support=20 (local beats project 50 beats global 0), release=0 (global only); 21 refused, op not run.
- developer inherits the shared folder from global; reads work root through the project permission.
- explicit empty list stops inheriting: reviewer refused the shared guide, dev allowed, reviewer still reads its own root.
- supplied value final: max_refund 5 beats the support default 20.
- deny in a higher layer not liftable: `.env` refused with `denied by permission global:1`, op not run; in-test control: the same call without the global deny is allowed by the local allow.
- layer order independent of the order the host lists layers.
- attributes written by an earlier Layer (auth) reach the decider (LP-14); declared after the policy Layer they arrive too late and the call is refused.
- allow with forced value (`overwrite:false`) is merged into the arguments the operation receives.
- no attributes: refused; aborted call: refused by the real decider (`the request was aborted`).
