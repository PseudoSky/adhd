# Phase B review triage: fixes to apply (one section per package)

Source: four blind reviews (R1 client, R2 entrypoint, R3 Layer, R4 gateway). Each item is a decision, not a suggestion. Items marked TEST are Phase C. Items marked DOC are README/AGENTS/docstring changes. Anything not listed is deliberately not fixed (it is filed to the backlog instead).

## Gateway (`packages/apigen/apigen-engine-gateway`, src/lib/sources)
G1 Retag the package `platform:node` in project.json (it imports node:child_process); run `npx nx graph`-equivalent checks via lint so dependents' boundary rules still pass; fix any boundary violation by retagging dependents ONLY if they are node-only, else stop and report.
G2 (security) Operation ids use the USER-CHOSEN source name, never the upstream's self-declared `serverInfo.name`: id = `<sourceName>.<tool>` where sourceName = sanitised `commandBaseName(command)`; add an optional `name` to `IResolveDeps`/resolve call so the wrapper can pass an explicit alias (`--name` on serve). Update D-08 in INTERFACES.md accordingly. Sanitised collisions inside one source are reported (skip + report, see G6).
G3 (security) `Operation.safe` is always `false` for MCP-sourced operations. Hints stay advisory in the side map only.
G4 Passthrough `tools/list` carries the FULL upstream Tool object (name, title, description, inputSchema, outputSchema, annotations) from a side map kept by the resolver; only `annotations` read-only/destructive hints are not rewritten.
G5 Passthrough bypasses positional dispatch: compose the Layer stack with `adaptCoreLayer` + a final `next` that calls the upstream `callTool(name, rawArguments)` directly (arguments verbatim, no schema-property mapping, no validate layer). Remove the positional wrapper dependence for MCP sources in passthrough (the resolver's `pkg.fns` may stay for other consumers).
G6 One bad tool never disables a source: a tool with a non-object inputSchema, a duplicate/colliding name, or a `__proto__`/`constructor` name is skipped and listed in a `skipped: {tool, reason}[]` field on the resolved source; the process logs one stderr line per skip through an injectable `onWarn`.
G7 Errors: other-than-denial failures return an isError result whose text is generic, AND are passed to an injectable `onError(err, ctx)` option (default writes one stderr line without argument values). Upstream McpError/validation messages from the upstream are passed through verbatim when the upstream itself returned them.
G8 Lifecycle: wire `server.onclose` and the upstream transport close to `shutdown`; when the upstream exits on its own, the server closes (host sees disconnect). Per-request cancellation: use the request's `extra.signal` for the Call signal.
G9 argv operation: honor `Call.signal`; add `timeoutMs` (default 120000) to `createArgvInvoker`; on abort/timeout kill the whole process group (spawn `detached: true` on POSIX and `process.kill(-pid)`), report `{exitCode: -1, signal}`; same group-kill on dispose/close of an MCP source. Keep the 1 MiB output cap; report the terminating signal.
G10 `nodeProcessLauncher` environment is an ALLOWLIST by default: PATH, HOME, USER, LANG, LC_ALL, TMPDIR, TERM, SHELL plus `spec.env`. (A caller passes more via `spec.env`.) DOC the change.
G11 Hardening: cap the transport line buffer at 8 MiB (error + close); attach a persistent `child.on('error')`; Map/null-prototype for tool-keyed tables; `commandBaseName` keeps versioned names (`python3.11` stays) and only strips known executable extensions (.exe .cmd .bat .js .mjs .cjs .py); delete the stale `node:path` comment.
G12 DOC README Sources section: states `bin:sh -c ...` is arbitrary execution gated only by the Layer; the env allowlist; hints are advisory.
G13 Update docs/plan/policy-core/T08-discovery.md deviations (G2, G3, G5).

## Client (`packages/policy/policy-core-client`)
C1 (security) `narrowAttributes`: supplied keys are checked too. A supplied key that is in `narrowingCovered` must satisfy `isWithin` against the parent (if the parent lacks the key => `exceeds-parent`); non-covered supplied keys (e.g. `role`) pass through as today.
C2 (security, fail-closed) `matches`/`matchesPresent` must not swallow engine exceptions: they throw, and `evaluateDetailed` catches and denies `eval-error` (FC-01) — for a deny rule that cannot be evaluated the whole call denies. `validateExpression` must also validate operands that are `$attributes.*` placeholders at evaluation time (invalid regex => throws => deny). `loadCompiled` runs `validateExpression` over every stored expression (unsupported operator => `PolicyLoadError('malformed')`), and range-checks `index` entries against `permissions`.
C3 Validator/property checks use `Object.prototype.hasOwnProperty.call` (schema validator, `hasPath`/`getPath`); `{constructor: 1}` and `attributes: {constructor:'bogus'}` must produce errors.
C4 DOC README + policy-reference: absent-attribute semantics stated plainly: every comparison on an absent attribute/field is false, INCLUDING negative operators, and so a `deny` conditioned on a missing attribute does NOT fire (pair with a positive guard); `_not` negates the false comparison (two-valued); `_is_null` is the presence test. Fix the `neutralizeAbsent` docstring that claims `_not` cannot flip.
C5 `defaults[].where` uses the same present-only semantics as `context` (`matchesPresent` in `resolveAttributes`).
C6 `draft`: docstring says `_` is literal (matches behavior); secret patterns also match a trailing slash and nested path segments (`/x/.env/`); list-valued path arguments: constraint applies with `_and` over elements is NOT supported — drafted policy marks list-valued path args as inferred 'list-valued: not constrained, review'.
C7 `findProjectFile` walk-up stops at an injectable `stopAt` directory (wrapper passes the user's home directory) and at the filesystem root; never adopts a file from an ancestor above `stopAt`.
C8 Performance: `ctx.policy()` caches by layer-file signature (path + mtimeMs + size via `IPolicyFs.stat?`) so an unchanged file skips read/parse/hash; `api.evaluate` resolves attributes once (pass the resolved result into the core evaluate via an internal parameter; public core signatures unchanged); the compiled predicate cache works for `_within` rows (cache by expression identity AFTER substitution is impossible, so cache the rewrite structure and substitute values per row).
C9 Audit/clock: `now()` and attribute-name extraction happen inside the audit try/catch; an audit record is written (decision `deny`, denialCode `eval-error`) when policy load/compile fails. Context row: an attribute named `runtime` is rejected at compile (`schema` issue: reserved name).
C10 DOC: `contentHash` detects corruption, not tampering; `_within` relative paths resolve against args `cwd` which the target tool must honor; supplied-attribute trust note (SC-08).
C11 `vite.config.mts` test environment `node`.

## Layer (`packages/apigen/apigen-plugin-policy`)
L1 (security) `readAttributes` builds the result with `Object.create(null)` via `defineProperty` and REJECTS any attributes object that has an own `__proto__` key (=> treated as no valid attributes => decider receives none).
L2 Add `onError?: (error: unknown, info: { phase: 'load' | 'decide' | 'timeout' | 'shape' | 'merge' }) => void` option; default writes one stderr line (no argument values). Client still gets the generic message.
L3 (security, verify first) Determine whether `call.envelope` can be populated from client-controlled input in the cli/mcp/fastify hosts (read `op-plan.ts computeEnvelopeFields`, hosts' envelope construction). If a client can set an envelope key the policy plugin does not declare, move the attribute channel to the call's `LayerContext` typed extension map (a key the auth layer writes; D-18 revised to `call.ctx`), and update INTERFACES.md, T07 and T09 (`attributes-layer.ts`, gate) accordingly. If envelope is host-built only from DECLARED fields, keep envelope and DOC that fact in the README with the code citation.
L4 Default export: ignore `mount.operations` calls with undefined opts once a config is captured; document one instance per process.
L5 `timeoutMs` invalid (non-finite, <=0, non-number) throws at construction/capture; on timeout fire an AbortController passed to `decide`.
L6 The decider receives shallow copies of `domainArgs` and `envelope` (frozen copies); `set` merge handles non-extensible `domainArgs` by throwing `ApiError('internal')` inside the try so the call still denies with the standard shape.
L7 `vite.config.mts` test environment `node`; add `exports`/`files` to package.json mirroring sibling plugins; fix tsconfig `module` residue to match siblings.

## Entrypoint (`entrypoint/policy`)
E1 `policyDistDir()` locates the bundle dir by trying `[here, here/dist, here/../dist]` and checking for `api.ir.json`/`cli.js`; `readPolicyVersion` reads the package.json next to the bundle or one level up; a stale/mismatched baked IR writes ONE stderr line before falling back to live extraction. Add a build-time check script that packs and runs from a non-`dist` directory is Phase C.
E2 `mcp-json --undo`: init writes `<file>.adhd-policy.bak` and a sibling `<file>.adhd-policy.json` containing the sha256 of what init wrote; `--undo` restores only when the current file's hash matches, else exits 2 with a message listing that the file changed; `--undo --force` restores anyway.
E3 Backup and rewrite use the original file's mode (backup `0600` if original unreadable by others), written atomically (temp file in the same directory + rename).
E4 Install abort handlers only when `argv[0]` is a verb; the apigen path keeps default signal behavior.
E5 `serve`: abort when the host transport closes or stdin ends; verify `serveMcpPassthrough` resolves on transport close (gateway fix G8) and exit 0.
E6 HTTP port: parse strictly (`/^\d+$/`, 0..65535) else `ApiError('invalid_argument')`; read via the Environment spec (no direct process.env in the entry file).
E7 DOC README: the identity source (`--adhd-attributes` / `ADHD_POLICY_ATTRIBUTES`) must be outside the control of the process being gated; confirm and document whether the child inherits `ADHD_POLICY_ATTRIBUTES` (and strip it from the child environment: the launcher allowlist (G10) already excludes it).
E8 `mcp-json init`: unmatched `--only` names => stderr warning and exit 2; an entry already wrapped under a different `--spec` is reported (`already-wrapped` with the old spec) and `--replace` rewrites its spec; spec path stored as given (relative stays relative when `--spec` was relative to the file's directory).
E9 `dereferenceSchema`: unresolved `$ref` or a cycle throws at extract/bake time with the ref path; move to `@adhd/apigen-core-client` ONLY if that package already exposes a schema-utils module; otherwise keep local and file the dedupe backlog item (no new shared package without approval).
E10 Hidden `ir-artifact` subcommand: ApiError => clean stderr + exit code via CLI_EXIT_CODE; `--out` must resolve under the package `dist/`.
E11 `splitPolicyArgv`: flag values starting with `--` are rejected; repeated `--adhd-attributes` is `invalid_argument`.
E12 `doctor`: any failed check => `ok:false` => exit 2 via the exit hook. cliPlugin info logging silenced at default level (wire `logging.level`). Extract the duplicated attribute-source construction into `wrapper/attributes-from-flags.ts`. README exit-code table rewritten as: 0 success/`evaluate` any decision; 1 internal/unloadable policy; 2 invalid input or verify/doctor failures; 3 `check`/`run`/`serve` refusal; 4 not found.
E13 Confirm `verify-dist-load` loads all three bins (the top-level `requirePkg` in ir.ts must not throw `ERR_PACKAGE_PATH_NOT_EXPORTED`); if the package.json export is not available, use a version constant generated at build.
