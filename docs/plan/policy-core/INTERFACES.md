# Interface contracts and decisions

Shapes are normative in `spec/architect-interfaces.md` (policy types, compiled schema, core API, service ops, ctx/ports), `spec/architect-interfaces-layer.md` (Layer port and plugin) and `spec/architect-interfaces-sources.md` (sources). This file pins package boundaries, resolves the demo's UNKNOWN list, and lists the contract each ticket must satisfy. Where this file and the spec differ, this file wins.

## 1. Package contracts
| Package | Path | Tags | Runtime deps | Root exports | Bins |
|---|---|---|---|---|---|
| `@adhd/policy-core-client` | `packages/policy/policy-core-client` | `domain:policy`, `pkg-kind:core`, `layer:logic`, `platform:node`, `access:public` | `@adhd/data-query-engine`, `@adhd/environment` (+`-base-spec`), `yaml` | the service operations (object-input form, below), `createDecider`, `createPolicyCtx`, spec types, port types | none |
| `@adhd/policy` (wrapper) | `entrypoint/policy` | `layer:entrypoints`, `platform:node`, `access:public` | client, apigen cli/mcp/fastify plugins, `@adhd/apigen-plugin-policy` | none beyond `package.json` | `adhd-policy` (+ `adhd-policy-mcp`, `adhd-policy-http`) |
| `@adhd/apigen-plugin-policy` | `packages/apigen/apigen-plugin-policy` | `layer:logic`, `platform:node` | `@adhd/apigen-core-client`, `@adhd/apigen-base-errors` only | default plugin, `makePolicyPlugin`, `PolicyAttributes`, port types | none |
Import edges: client → engine/environment only. Layer plugin ↛ client and client ↛ plugin (structural port; a contract test in the wrapper imports both). Wrapper → both. `exports` map of the client lists root + `package.json` only. Importing the client root starts nothing and loads no apigen/MCP/server code.

## 2. Decisions that close the demo's UNKNOWN list
| ID | Decision |
|---|---|
| D-01 (U3) | apigen operations take `ctx` as the first, schema-excluded parameter (verified: `entrypoint/backlog/src/api.ts` header; `createClient` supplies it per call). So `service/api.ts` exports `(ctx: IPolicyCtx, input) => Promise<result>` functions, and the **library entry** is `createPolicyClient(ctxOrLayers)` returning `IPolicyClient` whose methods take only `input` (object form: `client.evaluate({tool,args,attributes,runtime})`). `createMemoryCtx({layers,...})` builds a ctx with no environment. Positional `core` functions are internal (`src/core`, not importable). Demo S1 is rewritten to `createPolicyClient` in T18. |
| D-02 (U4) | Permission id is `<layer>:<n>`, `n` 0-based within that layer's `permissions` array. `IDecision.matched` lists every permission whose tool, context and args matched (allow, ask and deny), in evaluation order (layer order, then file order). |
| D-03 (U1) | Complex inputs (`args`, `attributes`, `request`, `layers`, `operations`, `options`) are JSON values. The CLI accepts whatever apigen's derived convention provides (JSON string or `@file`); T06 records the real form and T18 reconciles the demo. No hand-written flag parsing. |
| D-04 (U7) | Every refusal is `ApiError permission_denied` → exit 3: `check` on deny/ask, `run`/`serve` refused calls. Malformed input is `invalid_argument` → exit 2. |
| D-05 (U8) | `verify` returns `{ok, errors[], warnings[]}` listing **all** issues, never stops at the first. Exit 0 when `errors` is empty (warnings allowed), exit 2 when not. A policy that cannot be loaded makes every other operation fail closed with `internal` → exit 1 and a message naming the file; `check` never allows on a load failure (FC-06). |
| D-06 (U16/LC-01) | Wrapper attribute precedence: `--adhd-attributes` (JSON or `@file`) over `ADHD_POLICY_ATTRIBUTES` over none. Never merged: with both present the decision uses the flag's attributes only (the environment value contributes nothing, not even keys the flag lacks), proven through `run` and `serve` in T19 S8.3. File sources are re-read on every call (a changed `@file` changes the next decision inside one `serve` session). Non-object value refuses to start (exit 2). |
| D-07 (U6) | **Superseded** by ADR-0017 D2/D3: the operation id is `bin/<base>` (host `argv`, binding `bin:<base>`), not the bare basename. The `{argv, cwd}` input, the `args` matching and the `set` rules below are the shipped behaviour (`docs/policy-reference.md`). `bin:<cmd>` argv fallback: one operation whose id is the command's basename (`touch`), input `{argv: string[], cwd: string}`; `argv` excludes the command; `cwd` is absolute. Policy `args` match against `{argv, cwd}`. `set` forces `cwd` or replaces the whole `argv` array (`set: {argv: [forced.txt]}`, proven in T13). A dotted key such as `argv.0` is NOT an index: `set` writes keys as literal top-level properties, so `set: {'argv.0': x}` is silently ignored (the filter side, `args: {'argv.0': {...}}`, does read dotted paths). Index-wise forcing is open (filed in the Phase C part 2 report). |
| D-08 (U12) | **Superseded** by ADR-0017 D3/D7 for the id and the serving path: operations are `<sourceName>/<tool>` (rendered by `buildId`; `read_file` renders `read-file`), built by the gateway `mcp` extractor and served through `mcpPlugin.run` behind a gateway. The U12 start semantics stay in force: `serve` is an explicit start, the handshake is bounded, a failed handshake never falls back to argv and exits non-zero, and `Operation.safe` is always `false`. The text below that uses `<sourceName>.<tool>` is superseded. `serve <source>` is an explicit start. For `bin:` it performs an MCP `initialize` handshake with a bounded timeout; success ⇒ stdio MCP server, extract `tools/list` to operations whose id is `<sourceName>.<tool>`, where `<sourceName>` is the user-chosen alias (`name` option) or the sanitised command basename — never the upstream's self-declared `serverInfo.name` (D-23/G2); `Operation.safe` is always `false` for these operations (hints stay advisory, G3); a tool with a non-object schema, a duplicate or a reserved name (`__proto__`, `constructor`) is skipped and reported, never fatal (G6); failure ⇒ error (never silently falls back to argv): a silent upstream, a JSON-RPC error on `initialize` or `tools/list`, a process that exits, a command that cannot start or a plain program that prints text each exit 1 with the message on stderr, the host transport is never started and the process is gone (T19 S8.2). Denied tools stay listed (the call is refused); refusal is an MCP tool result with `isError: true` and the reason. |
| D-09 (U11) | `draft` returns `{document, yaml, inferred: [{operation, argument, kind, reason}]}`. Effect by hints: `readOnlyHint` ⇒ `allow`, `destructiveHint` ⇒ `deny`, otherwise `ask`. Arguments inferred as `path` get `_within` over `$attributes.read_roots` (read) or `write_roots` (write); the standard secret-path deny rules are included. Operation ids are used verbatim. A draft always passes `verify`. |
| D-10 (U5/U13) | Layer discovery: explicit `--spec <file>` / `layers` input, else walk up from the working directory for `workspace-policy.yaml` (stopping at the filesystem root, or at the injectable `stopAt` directory, inclusive, when the working directory is inside it; the wrapper passes the user's home directory, C7), else the user-global `global.yaml`, else the built-in deny-all default announced on stderr. `mcp-json init [--file p]` backs up to `<file>.adhd-policy.bak` (mode 0600, atomic writes), records the SHA-256 of what it wrote in `<file>.adhd-policy.json`, and rewrites `command`/`args`; `mcp-json --undo` restores the backup byte for byte only while the file still matches that record (a changed file exits 2; `--undo --force` restores anyway); a second `init` is a no-op; an unmatched `--only` name exits 2; an entry wrapped under another `--spec` is reported with the old spec and `--replace` rewrites it; a relative `--spec` is stored relative to the `.mcp.json` directory and an absolute one as given; `--force` is accepted only with `--undo` and `--replace` only with `init`; the file keeps its mode and a symlinked file is written through. Each clause is proven in T17 (E2, E3, E8). |
| D-11 (U9) | A tool is child-creating when any permission for it reads `args.child.*`. Narrowing coverage is computed per attribute from those filters (`narrowingCovered`); an uncovered granted attribute fails closed with `rule: "uncovered"`. |
| D-12 (U10/U2) | `explain.considered` lists every permission selected by tool name, in evaluation order, with `applicable`, `contextMatched`, `argsMatched`, `substituted` (paths unmodified). CLI output is the operation's JSON result (apigen cli-output default); policy source is announced on stderr as `policy: <path or built-in>`. |
| D-13 (U14) | `_within` over an empty list is false; relative or non-normalised paths are normalised against the call `cwd` when present, else compared as given after `path.posix.normalize`; non-existent paths are compared lexically (no fs access in core); implicit AND for multi-key objects; `_is_null` is a presence check. |
| D-14 (U15) | **Superseded** by ADR-0019 D1 and SPEC §7.1: the Layer is configured through `makePolicyPlugin({ decider, timeoutMs, ask, onError })`, and a host hands `createLayer(opts)` its flat `--opt` bag once per invocation (the plugin reads `timeoutMs`). The Layer receives its options (decider module + options) from `--use` options; if apigen hosts do not deliver them (LI-01), T07 documents the actual channel and the plugin also accepts options programmatically. |
| D-15 (OD-16) | `ask` is `permission_denied` (exit 3) until apigen has an approval result (backlog 7e7eb01d). The Layer calls an optional `IPolicyAskHandler`; with none, `ask` ⇒ deny. |
| D-16 | `IDraftOperation` is exactly the plain-data shape in `spec/architect-interfaces-sources.md` section 4 (`name`, `args[]`, `hints.readOnly`/`hints.destructive`); `IDraftOptions` adds `readRootsAttribute?`/`writeRootsAttribute?`; the result's `inferred` entries are D-09's `{operation, argument, kind, reason}`. The demo's `hints.readOnly`/`hints.destructive` are correct as written. |
| D-17 | Refusal exit code is 3 everywhere (D-04); the demo's "non-zero" wording is tightened in T18. |
| D-18 | **Superseded** by SPEC §8.1 rule 3: attributes travel on the call `ctx` under the `PolicyAttributes` class key exported by `@adhd/apigen-plugin-policy`, written by an earlier Layer; `call.envelope` is never read for attributes (`docs/attributes.md`). The envelope-key text below is superseded. Envelope key for attributes is `attributes` (`call.envelope.attributes`), written only by an earlier layer (the wrapper's attributes layer or an auth layer); the policy Layer never accepts attributes from anywhere else. L3 verified (REVIEW-FIXES.md): hosts fill `call.envelope` only from fields DECLARED by `--use` plugins (`op-plan.ts:240` `computeEnvelopeFields`; `compose-schemas.ts:196-204`; mcp `run.ts:287`, fastify `run.ts:232`, express `run.ts:190`, cli `run.ts:367`), and the policy plugin declares none, so a client cannot set `attributes`; the envelope channel is kept. No plugin may declare an envelope field named `attributes`. |
| D-19 | **Superseded** by ADR-0019 D1: options reach the Layer through `createLayer(opts)`, called once per invocation with the flat `--opt` bag; `mount.operations` capture is not used. The wrapper builds the Layer with `makePolicyPlugin`. `--use` options reach only a plugin's `mount.operations` capability (verified); the Layer plugin captures them there. The wrapper uses the programmatic `createPolicyLayerPlugin`. |
| D-20 | **Superseded** by ADR-0017 D1/D5/D7: source resolution (`resolveSourceReference`) and IR generation (`extractSourceEntry`) live in `packages/apigen/apigen-core-client`; the `argv` and `mcp` extractors and adapters live in `packages/apigen/apigen-engine-gateway`. The `bin:` source lives in `packages/apigen/apigen-engine-gateway` (existing package; OD-32), pending the T08 discovery's confirmation. |
| D-21 | **Superseded** by ADR-0017 D7 and ADR-0018 D2: `adhd-policy serve` runs the upstream as an MCP adapter behind a gateway and serves it with `mcpPlugin.run` and a terminal that calls `gateway.route`; refusals and every `ApiError` reach the host as `isError` tool results. `serveMcpPassthrough` remains in the gateway for hosts that do not go through the plugin. The injectable `hostTransport` and `handshakeTimeoutMs` ports and the shutdown conditions below still hold. `serve` over a `bin:` MCP source uses the gateway's `serveMcpPassthrough` (SDK Server + `createInvoker` + Layers), not `mcpPlugin.run`, so tool names, flat arguments and results reach an unmodified MCP host unchanged. A passthrough/flat-args mode in `apigen-plugin-mcp` is the alternative, filed as backlog, not built. The verb takes the host-facing transport and the handshake timeout as injectable `IVerbDeps` fields (`hostTransport`, `handshakeTimeoutMs`); the default is stdio over `process.stdin`/`process.stdout` with the gateway's 10 s handshake bound, so the bins are unchanged and a test drives the verb with an in-memory transport. Host disconnect, stdin end, upstream exit and the abort signal each end the verb with exit 0 and dispose the upstream (T17, E5). |
| D-22 | AT-10 is two-valued: a comparison on an absent attribute/field is false (including `_ne`/`_nin`), `_not` negates it, `_is_null` is the presence test. The same present-only rule applies to `defaults[].where`. A `deny` conditioned on a missing attribute does not fire; authors pair it with a positive guard. |
| D-23 | Phase B review fixes are specified in `REVIEW-FIXES.md`; where it changes a contract above (G2 operation id prefix, L3 attribute channel, E2 undo hash) it wins. |
| D-24 | Telemetry. The policy CLI writes metrics and event logs for auditing. Telemetry is on by default, records full detail, and is disabled through configuration (not through a feature-toggle environment variable). Each record carries the operation id, the decision, the reason and the inputs. The log file is created with mode 0600. A retention or size cap is required before ship; its value is an open owner item. |
| D-25 | `loadCompiled` is internal to `@adhd/policy-core-client` and is not exported from the package root. The client calls it, with CL-13 failure semantics (an unknown schema version, a hash mismatch or a malformed compiled policy fails the load), wherever it reads a precompiled artifact. The CC-04 text in `spec/architect-spec.md` and `spec/architect-interfaces.md` states the same. Backlog 52d194a1 is closed as this decision. |
| D-26 | Narrowing fails closed. When a `narrow` request defaults an attribute that the parent layer does not hold, the result is still `exceeds-parent`. Backlog 70c05230 records this as documented behaviour. |

## 3. Per-ticket contract checklist
- T02: every type in spec §2, §2.1, §2.2, §3, §4.2 exported from `src/spec`; two JSON Schemas (2020-12); a schema-vs-type test is a Phase C item.
- T03: `compile(layers, options?)`, `loadCompiled(json)` (internal, D-25), `createPolicyMemo`; compile is pure, byte-deterministic (canonical JSON), never throws on user input; `PolicyLoadError`/`PolicyCompileError`.
- T04: `evaluate`, `resolve`, `explain`, `narrow` exactly as spec §4.1-4.3; evaluate never throws.
- T05: operation set of spec §5 with D-01/D-05/D-09; `IPolicyCtx` thunk (lazy); `createDecider` matches the Layer port structurally; no `process.cwd()`, no fs in core.
- T06: three entry files each ≤ ~15 lines, no logic; baked IR; bins registered.
- T07: spec `architect-interfaces-layer.md` §2-§3; failure/malformed/timeout ⇒ deny.
- T08: `bin:` source per `architect-interfaces-sources.md` with D-07/D-08; `IProcessLauncher` port injectable (default spawns); `bin` is never executed during extraction unless `serve`/`run` was invoked.
- T09: `run bin:<cmd> --spec f [--adhd-attributes x] -- args`; `serve <source> --spec f`; `mcp-json`; `--adhd-*` flags stripped before the child sees argv.

## 4. Verified facts the file specs bind to
- `Query` and `DataView` are exported from `@adhd/data-query-engine`; `new Query({where: expr}).where` is a synchronous compiled predicate `(row) => boolean` (`packages/data/data-query-engine/src/lib/query.ts:73-110`). `matches(row, expr)` is therefore `new Query({where: expr}).where!(row)`; this closes IF-01. An invalid operator throws `QueryValidationError` (`lib/errors.ts:11`) — `validateExpression` catches it.
- `Layer = (call: Call, next: Next) => Promise<LayerResult>`; `Call` carries `operation.id`, `domainArgs`, `envelope`, `transport`, `signal?` (`apigen-engine-runtime/src/lib/invoke.ts:68-128`). A `--use` plugin is `UsePlugin = {id, capabilities?: {layer?: {layer(call, next)}}}` (`package-invoker.ts:36-80`); plug-in options ride on `options.useOptions[pluginId]` (`package-invoker.ts:86`).
- `new ApiError(code, message, details?)`; `CLI_EXIT_CODE` maps codes to exit codes (`apigen-base-errors/src/lib/errors.ts:58-125`).
- The CLI is mounted with `cliPlugin.run({packages:[pkg], operations, outputDir:'', options:{argv, usePlugins, exitCode?}})` where `pkg={id,version,schemas,importPath,fns,createClient}` (`entrypoint/backlog/src/cli.ts:1007-1040`, `server.ts:630-650`). `createClient` is called fresh per dispatch.
