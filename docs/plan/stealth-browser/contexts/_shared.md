## Glossary

- **[def:runner]** — the generic Chrome/CDP runner at `/Users/nix/dev/ai/scratch/agent-browser/adhd/` (CDP session, targets, launch, settle, capture, parsers, storage readers, domain wrappers, ChromeManager) plus the engine-agnostic queries `search/queries/{activity,context}.ts`. This is "the correct package" being migrated.
- **[def:src]** — `/Users/nix/dev/ai/scratch/agent-browser`, the scratch repo's agent-browser project (agent-search). Local-only git repo; read-only for every state except `search-cutover`.
- **[def:wt]** — `/Users/nix/dev/node/adhd/.worktrees/stealth-browser`, the single shared worktree (branch `stealth-browser`, cut from main c6011647). Every executor works here, in the same directory, on the same branch.
- **[def:pkg]** — the library package `@adhd/stealth-core-browser` at `packages/stealth/stealth-core-browser` (tier core, domain `stealth`, project `stealth-core-browser`), created by the workspace generator. The migration states (`mig-*`, `port-fixes`, `chrome-lifecycle`, ...) wrote this tree at `entrypoint/stealth-browser/` before `core-scaffold` moved it with `git mv`; every path in a state that runs after `core-scaffold` is under the core directory.
- **[def:search-pkg]** — the search entrypoint `@adhd/stealth-search` at `entrypoint/stealth-search` (project `stealth-search`, bins `stealth-search` and `stealth-search-mcp`), created by the workspace generator. It is the port of agent-search onto the built core package and carries every apigen/tracing requirement of the CLI and MCP hosts (`SPEC-stealth-search.md`, [ref:stealth-search-spec]).
- **[def:tripwire-pkg]** — `packages/resilience/resilience-core-tripwire`, the second approved package, `@adhd/resilience-core-tripwire` (tier core, new domain `resilience`, CJS-only per ADR-0003, zero dependencies, version 0.1.0). It is a kill-switch file protocol (a latch: first trip wins, a human or an explicit `open` policy clears it), not a record store, so ADR-0001 does not apply. Approved by the verbatim request recorded in `APPROVAL-tripwire.md`. Its three consumers: reverse-apis request-builder gate and unlock tool (`tripwire-reverse-migrate`) and agent-search (`agent-search-cutover`).
- **[def:bucket]** — a migration/test state's owned write scope. Buckets are directory-disjoint; `scripts/ownership.json` is the single source and `scripts/check-disjoint.py` proves concurrent states never overlap.
- **[def:psm-tag]** — every commit message ends `[psm:<state-slug>]`. The guard's ownership check reads these tags and fails if a tagged commit touches a path outside the state's owned set.
- **[def:telemetry]** — tracing records are written by `@adhd/sox-telemetry` after exactly one `initTelemetry({ service: 'stealth-search', role: 'cli'|'live-service', logSink: 'file' })` per bin (`src/telemetry.ts` of the search entrypoint); the apigen tracing namespace is `adhd` (`serviceName`), the telemetry SERVICE is `stealth-search`. Without `initTelemetry` the tracing plugin writes to a no-op sink and no log exists.
- **[def:ticket]** — backlog plan item `8468f7b1-8adc-4237-9986-21ea1e27c537` (adhd, in_progress). Tests cite its first 8 characters `8468f7b1` plus a `[<state>.N]` criterion id.
- **[def:verbs]** — the six chrome-runner verbs of the core library: `chromeStatus`, `launchChrome`, `shutdownChrome`, `listPageTargets`, `checkChromeActivity`, `getPageContext`; the search entrypoint projects eleven tools (`stealth_search`, `stealth_listProviders`, `stealth_describeProvider`, `stealth_tripwireStatus`, `stealth_clearTripwire` plus the six chrome verbs, `getPageContext` redacted).
- **[def:surfaces]** — library (the core package root), CLI (`stealth-search`), MCP server (`stealth-search-mcp`: stdio, sse, streaming-http).

## Cross-cutting invariants

- **[inv:one-new-package]** — exactly THREE new packages exist, all generator-built and all directed by the user: `packages/resilience/resilience-core-tripwire` (verbatim request `Implement tripwire package in this plan covering all 3`, `APPROVAL-tripwire.md`, [def:tripwire-pkg]), `packages/stealth/stealth-core-browser` ([def:pkg]) and `entrypoint/stealth-search` ([def:search-pkg]) (verbatim request in `APPROVAL-split.md`; the original `entrypoint/stealth-browser` approval in `APPROVAL.md` is carried by the core package). No fourth project.json may be added; the former nested `@adhd/cdp-connection` package does NOT travel (it becomes `src/lib/cdp/`). Guarded by `scaffold.5`, `tripwire-scaffold.5`, `core-scaffold.6` and `search-scaffold.4`.
- **[inv:shared-worktree]** — all executors work in the same worktree and branch. Stage only your own explicit paths (`git add <path>`); never `git add -A`/`.`/`commit -a`, `git stash`, `git reset --hard` or `git clean`. Never revert another state's changes.
- **[inv:owned-paths-only]** — a state writes only its `mutates` set (= `scripts/ownership.json` entry). Plan bookkeeping (`state.json`, `events.ndjson`, `docs/plan/plan-index.json`) is exempt.
- **[inv:source-untouched]** — `/Users/nix/dev/ai/scratch/agent-browser/adhd/` and every agent-search file stay byte-identical to the baseline commit in `evidence/source-baseline.txt` until the first `search-cutover` commit (guard `source_untouched` reads the baseline tree from git, so the cutover may delete `agent-browser/`). The live MCP source keeps working throughout.
- **[inv:no-main-writes]** — never write to `/Users/nix/dev/node/adhd` (the main checkout) except the dispatcher's ff-only merge. Its `node_modules/.modules.yaml` mtime is stamped and re-checked.
- **[inv:node-modules]** — `scaffold` symlinks the main checkout's node_modules (read-only, generator/nx only); `deps-install` replaces it with a real worktree install before any `pnpm add`. Never install through the symlink.
- **[inv:worktree-required]** — monorepo (nx.json, pnpm-workspace.yaml present): every executor works in the git worktree above, never the main checkout; a worktree that needs node_modules symlinks the main one, it does not reinstall (exception: `deps-install`, which must change the lockfile and therefore owns a real install).
- **[inv:pnpm-only]** — pnpm@8.15.9 with the machine-wide store (`~/Library/pnpm/store`); never npm/yarn.
- **[inv:esm-js-specifiers]** — relative imports use `.js` specifiers (sibling convention); the source's `.ts` specifiers are rewritten during the port. No committed compiled `.js` twins.
- **[inv:search-over-core]** — `@adhd/stealth-search` consumes the BUILT `@adhd/stealth-core-browser` package (one core module graph); it never opens a CDP socket or spawns Chrome except through the core's `cdp.*`, `capture.*`, `chromeManager` and `lifecycle` namespaces, never reaches into the core's `src/`, and reads no environment variable (every former `SEARCH_*` toggle is a typed option or host flag, ADR-0001).
- **[inv:stealth]** — Chrome is launched with `--remote-debugging-port` and WITHOUT `--enable-automation`; no `Runtime.evaluate` anywhere (DOM walks only). Behavior-preserving port: these are the runner's reason to exist.
- **[inv:live-chrome]** — the developer's live Chrome on port 9222 is sanctified: no test, guard or script may `pkill`/`killall`/`lsof`-kill it or connect to 9222. Unit tests mock process spawn and run against the in-memory harness; the simulated lifecycle uses `FakeProc` and kills nothing real.
- **[inv:trace-namespace]** — apigen tracing lives in the search entrypoint: `makeTracingPlugin({ serviceName: 'adhd' })` configured once in `entrypoint/stealth-search/src/tracing.ts`, mounted in every `usePlugins` array of the CLI and MCP hosts, with exactly one `initTelemetry` per bin in `src/telemetry.ts` ([def:telemetry]); the package's own `tracingPlugin` singleton (namespace `apigen`) is never imported. Records are `adhd.<op>.start|finish|error`. The core library has no host, no apigen dependency and no tracing. Log files are validated by the `tracing-log-validation` agent, not by tests.
- **[inv:unit-purity]** — the unit lane (`*.spec.ts`) has no subprocess, no network, no real Chrome, no real profile: `child_process`, WebSocket/`fetch` and fs touch points are mocked.
- **[inv:tests-cite]** — every spec file cites the ticket `8468f7b1` and at least one valid `[<state>.N]` criterion id.
- **[inv:use-case-sim]** — there is no live-Chrome e2e lane (user decision). Behaviour is proven by use-case unit suites that simulate real scenarios through the shared harness (`FakeCdpServer` with `vi.stubGlobal` WebSocket, `MemFs`, `FakeProc`, fixtures labelled `synthetic-protocol-conformant`), named after what a user is trying to do, plus the agent-search cutover as the real-consumer integration proof.
- **[inv:no-features-removed]** — user direction: every FEATURE and FAILSAFE of the source runner (behavior a user or the system relies on: the three idle-safety tiers including history recency and `checkHistory`, the O_EXCL launch lock, process-group kill, the newtab fix, livelock protection, cross-process coordination, isolated-page cleanup, ban detection, graceful capture outcomes, read-only profile access, the stealth flags) is preserved and pinned by a NEW feature-level unit test. Legacy code is NOT preserved (greenfield): code structure, file layout, internal and legacy export names, legacy error-message substrings, line-similarity/manifest guards, the heartbeat file path as such and tests that enshrine buggy or legacy behavior may change freely; a mechanism (heartbeat file, lease registry, service proxy) may be replaced when every behavior it provides stays. `evidence/failsafe-inventory.json` (built first by `failsafe-inventory`) lists each feature with its source file:line and the pinning test (`[fs-NNN]` in the spec); owner states pin their rows and `audit-pre-review`, the `review-prep` gate and `audit-final` re-check every row. Removing a feature needs explicit user approval. The capture/dom.ts Google-SERP walker is a feature kept unless the inventory shows it is only a search-provider leftover (flagged to the user, not decided here).
- **[inv:greenfield]** — the package is new and public: no consumers exist, so no legacy file, subpath, alias, deprecation or compatibility shim is ever added; the source is corrected, never aliased (ADR-0002). Names: root namespaces `cdp`, `storage`, `capture`, `parsers`, `chromeManager`, `recording`, `lifecycle` and six flat verbs.
- **[inv:typed-errors]** — every failure a user can hit is a typed error with a stable code: `StealthCoreBrowserError` in the core (library, capture and lifecycle codes, `prod-errors`) and `StealthSearchError extends StealthCoreBrowserError` in the search entrypoint (search, guard, fetch, host and tripwire codes, `search-errors`); no untyped `Error` in non-test source of either package.
- **[inv:cutover-live-vs-recorded]** — `search-cutover` proves the unreleased build with tarballs of the three packages (tripwire, core, search) packed from this worktree outside every `.worktrees/` directory and installed as real directories in a scratch temp consumer (no committed link, no lockfile change); the consumers (agent definitions, MCP host configs) are rewritten only by `consumer-relink` after the three packages are published in dependency order (tripwire, core, search). `evidence/cutover/live-vs-recorded.md` states precisely what is LIVE, RECORDED and NOT-CHANGED.
- **[inv:pre-review-not-blind]** — `audit-pre-review` is a static, non-blind audit whose findings `audit-fixes` resolves with ONE implementer; `audit-migration-blind` remains the single blind review.
- **[inv:one-implementer]** — one implementer resolves every pre-review finding and every blind-review finding; findings are never split across implementers.
- **[inv:blind-review]** — the reviewer receives the diff and the single word `Review`: no context, rationale, review points or prior state.
- **[inv:scratch-local-only]** — the scratch repo is local-only: never push; no PII in commits; stage explicit paths because its working tree carries other projects' uncommitted edits.
- **[inv:gate-trees]** — gate evidence is keyed by `code_tree` (src, bin, package.json and project.json of each package: core, search, tripwire) so the docs states (`docs-marketing-run`, `readme-rewrite`) can edit README, CHANGELOG, docs/, AGENTS.md and llms.txt after `gates-rerun` without invalidating it; any change to a package's src, bin or manifest after the gates invalidates them.
- **[inv:no-ai-attribution]** — no AI-disclosure lines in commits, docs or README.
- **[inv:test-layout]** — main's test layout (`docs/standards/testing.md`, ADR-0009 amended; `check-test-layout.mjs` L1-L9) governs all three packages from the 2026-10-23 amendment on. Tests live in `<project>/test/` whose only children are `unit/`, `e2e/`, `helpers/`, `fixtures/`, `golden/`, `setup.ts`; nothing test-shaped lives under `src/`; every file under `test/unit` is a `*.spec.ts(x)` (the unit lane is `UNIT_FILE_INCLUDES`); no e2e lane exists unless `check-lane-reachability.mjs` demands one. The pinned move table (conform states move exactly like this; guards resolve exactly these locations): `src/test/unit/**` -> `test/unit/**`; `src/test/use-cases/*.spec.ts` -> `test/unit/use-cases/`; `src/test/support/*` -> `test/helpers/`; `src/test/fixtures/**` -> `test/fixtures/**`; a non-spec `.ts` beside specs (`unit/<area>/harness.ts`, `*-kit.ts`, `fake-*.ts`, `*-fixture.ts`, `browser-mocks.ts`, `manager-*.ts`, `host-fixture.ts`) -> `test/helpers/<area>/<file>`; html/pdf fixtures beside specs (`unit/<area>/fixtures/**`) -> `test/fixtures/<area>/**`. A spec reaches src as `../../src/...`. Every spec's first comment block (first 60 lines) carries `guards:`, `tier: S` and `cites:`; `test-headers.baseline.json` is never touched. Contexts and guards of completed states keep their historical `src/test` wording; their guards resolve the new locations.
