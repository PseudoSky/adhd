- The parity harness is authored in `apigen-engine-runtime/src/test-support/` and imported by four other plugins' spec files. The exact export plumbing (a `@adhd/apigen-engine-runtime/testing` subpath export vs. a deep relative import vs. a tiny dedicated test-support entry) is left to the `parity-harness` executor within its reservation. Decide in `parity-harness`; if a new package turns out warranted, it MUST go through `npx nx g @adhd/workspace-codegen-nx:<tier> --group apigen` (never hand-created).

## Filed deferrals (review folds)

### DEFER-APIGEN-SERVE-CORE-PYGRPC-STREAMING-001 — py-grpc does not serve streaming ops (scope boundary, not a capability verdict)
- This epic's py-grpc extract/serve split (`FEAT-APIGEN-SERVE-CORE-009`) explicitly REJECTS `streaming:true` ops rather than serving them, matching CLI. gRPC natively supports server streaming and a consumer will want it — so this is a DOCUMENTED, tracked deferral (dod.5, [fix:pygrpc-streaming-deferral]), NOT a permanent no. Re-open as its own item to wire gRPC server-streaming through the injected plan once a consumer needs it.
- Citations: [apigen-serve-core-planbuilder, claude (opus), apigen-serve-core, 1: docs/plan/apigen-serve-core/contexts/py-grpc-serve-split.md (Review folds); 2: docs/plan/apigen-serve-core/README.md dod.5]

## Bugs discovered during execution

### BUG-APIGEN-SERVE-CORE-CRITERIA-CWD-001 — every criterion in scripts/criteria.json is missing `"cwd":"repo-root"`, so `state-transition.js --complete` spuriously FAILs `present`/`command` checks whose paths/cmd are repo-root-relative
- **Discovered:** 2026-07-23/24, `serve-core-primitives` state completion. `node "<skill>/scripts/state-transition.js" ... --complete` returned exit 4 (`audit_failed`, `audit_criteria_passed:3`, `audit_criteria_total:21`) reporting ALL NINE `[serve-core-primitives.1]`..`[.9]` criteria as FAIL — including trivial index-export/cliFlags/envVar presence checks that are demonstrably true in the delivered code (verified independently below). The state DID still advance (`state.json` shows `serve-core-primitives.status:"complete"`, `current_state:"parity-harness"`, `end_ref` = the real commit) — this bug is about the audit's REPORTED result being wrong, not about the transition mechanics.
- **Root cause (confirmed empirically, not guessed):** `run-audit.js`'s `resolveBase(c, cwd, repoRoot)` (`docs/plan/apigen-serve-core/scripts/run-audit.js:229-231`) returns the runner's own `cwd` unless a criterion opts in with `"cwd":"repo-root"` (the "BL-96(1)" migration documented in that file's header, `run-audit.js:19-41`). `state-transition.js`'s `runAudit()` always invokes `node scripts/run-audit.js` with `{ cwd: planDir }` (the plan directory, `docs/plan/apigen-serve-core/`), never the repo root (state-transition.js `runAudit()`, the `spawnSync("node", [...], { cwd: planDir, ... })` call). Every criterion in `scripts/criteria.json` (all 59, confirmed by script: zero have `"cwd":"repo-root"` set) uses a repo-root-relative `paths`/`cmd` (e.g. `serve-core-primitives.1`'s `paths:["packages/apigen/apigen-engine-runtime/src/index.ts"]`, `serve-core-primitives.6`'s `cmd:"CI=true ./node_modules/.bin/nx run apigen-engine-runtime:test"`). Reproduced directly: `cd docs/plan/apigen-serve-core && node scripts/run-audit.js --phase phase-1 --repo-root <repo>` → every `present`-kind serve-core-primitives criterion FAILs (file lookup resolves to `docs/plan/apigen-serve-core/packages/apigen/...`, which does not exist) and every `command`-kind criterion FAILs with `exit=127: /bin/sh: ./node_modules/.bin/nx: No such file or directory` (same relative-path-from-wrong-cwd cause).
- **Why the earlier ad-hoc `python3 docs/plan/apigen-serve-core/scripts/audit_apigen-serve-core.py --phase phase-1 --repo-root <repo>` invocation (run from an ambient cwd of the repo root) misleadingly PASSED:** that legacy wrapper's `subprocess.run(cmd, capture_output=True, text=True)` call (`audit_apigen-serve-core.py:111`) does not pass `cwd=`, so it inherits the CALLING shell's cwd — repo root, by accident of how I invoked it — not `state-transition.js`'s real, hardcoded `cwd: planDir`. This made a manual audit run give a false-positive "all green" signal that does not match what `--complete` actually sees.
- **Independent proof the underlying code is correct** (so this is purely an audit-plumbing bug, not a code defect): `CI=true ./node_modules/.bin/nx run apigen-engine-runtime:test` from the repo root exits 0 (23/23 new + 180/180 total tests green); `nx run apigen-engine-runtime:lint` and `:build` (which type-checks via `vite-plugin-dts`) both exit 0; manual `grep` of `readUsePlugins`/`transport`/`envVar` in the cited files confirms every pattern is present.
- **Impact:** ALL 59 criteria across the WHOLE plan (not just `serve-core-primitives`) are affected — every future state's `--complete` will report the same false "audit_failed" for its own criteria, and the `final`/`dod.*` gate (which reads these same per-state PASS/FAIL lines) will never be able to confirm DoD honestly until this is fixed. Non-blocking per-state (states still advance on guard-pass), but it defeats the audit's actual purpose (verifying acceptance criteria) for this entire plan.
- **Fix direction:** add `"cwd": "repo-root"` to every `present`/`command`/`negative-control` criterion in `scripts/criteria.json` whose `paths`/`cmd`/`mutate`/`positive`/`restore` are repo-root-relative (i.e. essentially all of them) — a mechanical, scriptable edit. Out of scope for `serve-core-primitives`'s file reservations (`scripts/criteria.json` is plan infrastructure, not a reserved `mutates` file); needs a planner-class fix (touches the whole plan's audit surface across every remaining state), reported to the orchestrator rather than hand-fixed here.
- **Status:** OPEN — reported to `apigen-serve-core-orchestrator` 2026-07-24. Does not block `serve-core-primitives` (already advanced) but should be fixed before the NEXT state's `--complete`, or every subsequent state will hit the identical false-FAIL noise.
