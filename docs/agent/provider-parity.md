# Provider parity: behavior x provider matrix

Which agent-runtime behaviors apply equally to every provider, and which do not. Every row cites the code that decides it.

## Providers

Only three provider adapters exist; the factory switch is exhaustive and throws on any other type (`packages/agent/agent-engine-orchestrator/src/providers/factory.ts`).

| Column in the matrix | Adapter     | File                                                                                                                                                |
| -------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| anthropic            | `anthropic` | `packages/agent/agent-engine-orchestrator/src/providers/anthropic.ts` (+ `anthropic-cache.ts`)                                                      |
| openai / DeepSeek    | `openai`    | `packages/agent/agent-engine-orchestrator/src/providers/openai.ts`                                                                                  |
| claudecli            | `claudecli` | `packages/agent/agent-engine-orchestrator/src/providers/claudecli.ts` (+ `claudecli-session.ts`, `claudecli-tool-bridge.ts`, `claudecli-bypass.ts`) |

"OpenAI-compatible" endpoints, DeepSeek included, are the `openai` adapter plus a `baseURL` override. There is no separate `deepseek` or `gemini` adapter (`entrypoint/agent-mcp/README.md` provider table). `@adhd/apigen-plugin-openapi` is unrelated.

Legend. **applies**: honoured, either by a provider-agnostic layer or natively. **gap**: this provider lacks an equivalent it should have. **n/a**: inherently one provider's concern; the others do not need it.

## Budget pricing

The `cost` cap is priced per model turn from the shared rate card, never per provider. A DeepSeek agent on the `openai` adapter is priced at DeepSeek's rates and a Sonnet agent at Sonnet's with no provider-specific configuration.

`pricing` is a top-level budget plugin key (`pricingModeSchema`, `packages/agent/agent-plugin-budget/src/index.ts`):

| `pricing`        | Behavior                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| `auto` (default) | Explicit flat `costPer*Token` rates win; with none configured, the rate card prices the turn.             |
| `rate-card`      | The rate card prices every turn; flat rates apply only as the fallback for a model the card cannot price. |
| `flat`           | Only the configured flat rates price a turn; the rate card is never read.                                 |

Precedence: explicit per-agent / per-provider rate override, then `defaults.costPer*Token`, then the rate card. Cache-read and cache-write rates default to the input rate whenever flat rates price a turn: in `flat` mode, with explicit flat rates in `auto`, and in the `rate-card` fallback (`flatRatesOf`, `packages/agent/agent-plugin-budget/src/index.ts`). The model is the one the engine requested, not the one the provider reports: the resolved wire model, else the selection's `modelRef`, else the agent's inline model (`requestedModelOf`, `packages/agent/agent-plugin-budget/src/index.ts`). The provider's `responseModel` is not consulted, so the cap prices the same model `usage_query` reports. Full reference and the migration note: `packages/agent/agent-plugin-budget/README.md#cost-pricing`.

Host behavior: the budget defaults builder in `entrypoint/agent-mcp/src/config.ts` (reads `ADHD_AGENT_BUDGET_COST_USD`) sets `pricing: "rate-card"` for that cap instead of injecting flat Sonnet rates.

An unpriceable model is never a silent $0. With flat rates configured the turn bills at them; otherwise it accrues nothing and one `budget:unpriced_model` event is emitted per task and model (payload `model`, `field: "cost"`, `usedFlatRates`, `message`).

## Task events

Two typed event types are persisted in `task_events` alongside `MODEL_REQUEST`, `MODEL_RESPONSE`, `TOOL_CALL`, `TOOL_RESULT`, `TOOL_ARG_COERCED`, `TASK_COMPLETED`, `TASK_FAILED` and `TASK_CANCELLED` (`TaskEventType` in `packages/agent/agent-engine-orchestrator/src/validation/task.ts`; DB enum `packages/agent/agent-store-runtime/src/db/schema.ts`):

- `budget:unpriced_model`: a model had no rate-card price during cost-cap accounting (above).
- `provider:builtin_bypass`: a claudecli agent enabled CLI built-ins; emitted once per task (and live built-in set), not per model turn. Payload: `source` (`allowedBuiltinTools` | `compiledTools` | `agent-spec`), `builtins`, `skipped`, `advice`. Silent for the default-deny case. On the `allowedBuiltinTools` and `compiledTools` paths `builtins` is the post-gate set, so it never lists a built-in the permission gate withheld; on the `agent-spec` path it echoes the spec's `tools:` header (or `*` when the header cannot be parsed) without gate filtering.

## Built-ins (claudecli)

CLI built-ins (Bash, Read, Edit, Write, ...) execute inside the `claude` process. They are default-deny: a claudecli agent that sets no `allowedBuiltinTools` is spawned with `--tools ""` (`computeClaudeBuiltinArgs` in `claudecli.ts`), and each requested built-in is further gated by the engine's `claude-builtin.<Tool>` permission verdict. The bypass therefore exists only when an agent opts in, or in agent-spec mode where the spec's `tools:` header governs. The header is read by a best-effort parser that handles the inline (`tools: A, B`), flow (`[A, B]`) and block (`- A`) forms; other YAML (folded or literal scalars, anchors) may be misread, and an absent or empty header lists `*`.

For an enabled built-in the engine supplies only the permission verdict. It skips: hooks (including the EOL/CRLF hook), argument coercion, the tool-result size cap, the token estimator and the concurrency pool (`BUILTIN_SKIPPED_BEHAVIOURS`, `claudecli-bypass.ts`). The recommended path is to route file work through the bridged `fs__*` tools, which pass through all of them.

CRLF finding (single sample per case, `claude-haiku-4-5`, `--permission-mode acceptEdits`): the CLI's built-in Edit preserves a uniformly CRLF file, and strips every CR from a mixed-ending file, including on untouched lines (n=1; a larger sample is tracked in the backlog). Treat built-in Edit/Write as unsafe for mixed-ending files.

## Limits stated plainly

- `reasoningTokens` of 0 or absent means "not itemised by the provider", not "no reasoning". Anthropic folds thinking tokens into `output_tokens`, and claudecli does not report them. Only the `openai` adapter itemises. Cost is unaffected either way.
- Partial usage on a failed attempt is recorded for claudecli only. Extending it to the API adapters is deferred until a billed failure is shown (tracked in the backlog).
- The engine-wide limiter is per task. A child task spawned by a bridged `task` call has its own limiter, so a parent holding the only slot (`toolCallConcurrency: 1`) never waits on a slot its child needs. `request_human_input` calls bypass the pool.
