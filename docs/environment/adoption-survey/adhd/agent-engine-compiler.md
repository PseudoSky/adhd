## Gap detail

| Gap | Detail |
|-----|--------|
| **G1** | `REGISTRY_DATABASE_PATH`, `DATABASE_PATH`, `AGENT_REGISTRY_DB` do not follow the `ADHD_*` env-prefix convention. A cascading environment cannot remap these under a single namespace prefix without hardcoding the three alternative names. The env abstraction requires a single canonical env name per field (possibly with an override like `envPrefixOverride`), not a choice list. |
| **G2** | Writes occur in three locations: `./data/registry.db` (repo-relative), `~/.agent-registry/registry.db` (custom homedir, not `~/.adhd`), and `./drizzle` (repo-relative cache). Environment currently assigns all `kind:data` paths under `~/.adhd/<project>/<namespace>/data/`, not a mix of repo-root-relative and homedir paths. The CLI's fallback to a non-standard homedir path must be reconciled with the environment's `~/.adhd` scope hierarchy. |

## Logging audit

The package **does emit logs**, but only at the CLI boundary:

- **Logger mechanism:** `process.stderr.write()` — bare Node console stderr, not a framework.
- **Log files:** No — logs are written only to stderr, never persisted to disk.
- **Structured?** No — plain text messages like `"agent-compiler: warning: migration folder not found: ..."` (line 224–226, `src/cli/compile.ts`).
- **Error handling:** Adhoc try/catch at the CLI level (`src/cli/compile.ts:245–260`). The compilation function `compileAgent()` propagates errors up; the CLI catches them and exits 1. No structured error logging.

**Would this package benefit from `env.paths.logs`?**

Yes, conditionally. The package currently writes nothing to disk, but:
1. A persistent log file could capture migration runs and CLI invocations (useful for debugging registry schema evolution).
2. The per-instance `share: 'per-instance'` guarantee would prevent log collisions if multiple agent-compiler instances run concurrently (e.g., in a monorepo build graph).
3. Structured logs (JSON) from drizzle migrations (via Drizzle's migration hooks) would aid observability.

**Recommendation:** Adopt `env.paths.logs` and wire Drizzle's migration logger to emit to `${env.paths.logs}/migrations.log`. Update the CLI to optionally log compilation start/end and error details to `${env.paths.logs}/compile.log` (e.g., when `COMPILER_VERBOSE=1`).
