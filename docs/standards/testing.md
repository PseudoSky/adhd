# Testing IMPLEMENTATION — adhd

Adopts the testing strategy at docs/testing/STRATEGY.md (v0.4). Names no agent. Generated by `/workspace-standards apply testing`; edit only inside the hand-maintained region.

**Test file layout.** A package keeps its tests in `<package>/test/`, outside `src/`: `test/unit/` holds the `test` lane (`*.spec.ts`) and `test/e2e/` holds the `e2e` lane (`*.e2e.ts`, `*.e2e.test.ts`). Each lane mirrors the `src/` tree, so `src/write/tx.ts` is covered by `test/unit/write/tx.spec.ts`. The vitest `include`, `tsconfig.spec.json` `include`, `E2E_FILE_INCLUDES` (`tools/vite-plugins/e2e-globs.mjs`) and the `production` input in `nx.json` all cover `test/`. A test reaches its subject by a relative import into `src/`; a path built from `__dirname` or `import.meta.url` is anchored on the test file, not on `src/`. Files not yet moved (`src/**/__tests__`, `src/test/{helpers,fixtures}`) stay discoverable through the `src` globs.

**Owner:** the repository maintainer (git `pseudosky`), who is also the risk owner, the X-tier authorizer, and the holder of every role no other party holds. **Conformance level: none (below L1).** The checker prints this from the binding table at the end of this file: `node ~/.claude/skills/workspace-standards/scripts/testing-level.mjs --implementation docs/standards/testing.md`. L1 needs G1, G2, G4, G5, G6, G10 and G12 enforced; G1, G2, G4, G9, G10 and G12 are (G12 checks commits from 2026-10-20), and G5 and G6 are listed as obligations below with a mechanism and a review date.

Terms used in the binding table. **Mechanism class:** C0 no mechanism; C1 text a reader is expected to follow (an instruction file, a card, a template); C2 review by a party other than the author; C3 a mechanical check run on demand or by the gate engine; C4 a mechanical check that blocks at a hook or in CI. **Status:** `enforced` means a command or review named in the row runs where the row says and refuses the change; anything else is `obligation, not yet a gate`.

1. **Tier mapping.**
   - **Tier S** — unit tests: `*.spec.ts`, `*.test.ts` and `*.spec.mjs` beside the source, run by the project's `test` target (Vitest, or `node --test` for the build tools). Ceiling, budget and the split-or-fix threshold are the strategy's (100 ms p95, 1 s). Source of truth for membership: the file name plus the project's `test.include`. Subprocesses, sockets and fixed sleeps are not allowed in tier S ([ADR 0009](../decisions/0009-test-lanes-unit-vs-e2e.md)); a `node --test` spec that spawns node, git or sh is tier P, whatever its file name.
   - **Tier P** — `*.e2e.ts` and `*.e2e.test.ts`, run by the project's `e2e` target (`npx nx affected -t e2e --parallel=1`) in an isolated working directory and a fake `HOME`. Budget 10 s per test. Every `*.e2e.ts` has a paired `*.spec.ts` stub so the tier S lane lists the suite. The build-tools specs run in two `node --test` lanes of the root `package.json`: tier S specs (`*.spec.mjs`) in `test:build-tools` (the `test` target of `tools/nx-plugins`, which pre-push and both CI workflows run), and specs that spawn node, git or sh against a temporary directory, tier P with the same 10 s budget and named `*.e2e.mjs`, in `test:build-tools-e2e` (its `e2e` target, CI only). A file is classified by its heaviest case. The local pre-push hook runs tier S only: `check-test-headers.mjs` rule H5 fails a tier P, H or X header in a file not named `*.e2e.*`, and lane-reachability rule 10 fails a build-tools e2e spec that the pre-push script lists or that no script reaches. `smoke` subset: the `verify-dist-load` targets plus each package's published-layout e2e.
   - **Tier H** — no lane exists yet. The suites that need a foreign runtime (the Python and gRPC apigen plugins) run in tier P today and are reclassified when a tier H lane exists; that is a migration item (section 8). Budget when it exists: 2 min.
   - **Tier X** — the live-provider suites (`entrypoint/agent-mcp/src/__tests__/integration/live-*.e2e.test.ts`, `entrypoint/dispatch-cli/src/test/integration/live-dispatch-five-acs.e2e.test.ts`). Authorized by the repository owner (D7). Each is gated by an environment flag documented in the owning package README, `AGENTS.md` and the test file header; with the flag set a missing credential is a loud failure. **No stage sets the flag today**, so G2 does not hold for tier X; section 8 records this.

4. **Decision-tree bindings.** Worked examples, one per branch of STRATEGY §6.2:
   - Pure logic, parser or validator: tier S, `*.spec.ts` beside the source (for example `tools/nx-plugins/test/metrics/tiers.spec.mjs`).
   - A store or engine wired together: tier S with a real in-process datastore and an in-memory transport (the `buildHarness` fixture in `entrypoint/agent-mcp/src/__tests__/integration/harness.ts`).
   - A built CLI or server started as a consumer starts it: tier P, `*.e2e.ts` plus the paired `*.spec.ts` stub (`entrypoint/backlog/test/e2e/testing-record.e2e.ts`).
   - A hook or script that rewrites tracked files: tier S or P against a temporary copy of the workspace, never the live file (`.githooks/pre-push.e2e.mjs`).
   - A foreign runtime: tier H (not yet laned; section 8).
   - A paid or shared service: tier X behind the documented flag.

   Header syntax for every new test is `standards/testing/formats/test-header.md` of the installed `workspace-standards` skill: `guards`, `tier`, `gap` (tier P, H, X only), `cites`, `tags`, `teeth`.
5. **Retention bindings.** Triggers are detected by the retention review the strategy defines (`/workspace-standards run testing` → retention-audit playbook) over the gate report, the Nx run history and `git log` on test files; the refactor-edit trigger uses the 90-day window of section 9a. Exception log: backlog items carrying an `expires:` line in their testing record and a `relates_to` link to the item they excuse (the convention is in `entrypoint/backlog/skill/SKILL.md`, "Testing record"). Escape records live on the defect item as the fields of `standards/testing/formats/escape-record.md`. Removal records live on the item of the change that removes the test.

9. **Class and rigor bindings.**

   *Escalation triggers and how they are detected.* The routing command (`node tools/nx-plugins/test/routing/test-routing.mjs`) reads the table below from this file: the `id`, the minimum rigor, and every backticked glob in the last column. A change whose changed files match a glob hits that trigger. A trigger no path can show (a `package.json` field change, an MCP tool `inputSchema` change, the irreversibility of an effect) is asserted in the item's testing record with `triggers:`; an asserted trigger raises the derived rigor and never lowers it.

   | id | Trigger | Minimum rigor | Path patterns |
   |---|---|---|---|
   | boundary | Crosses a process, network or ownership boundary | Standard | `entrypoint/*/src/**/mcp/**`, `entrypoint/*/src/**/server*`, `**/*.proto`, `**/schema.json` |
   | entrypoint | Alters a shipped artifact's entry point | Standard | `entrypoint/*/src/index.ts`, `entrypoint/*/src/main.ts` |
   | persistence | Touches persistence or concurrent writers | Deep | `**/migrations/**`, `**/drizzle/**`, `**/store/**`, `**/*-store.ts` |
   | security | Security-relevant | Deep | `**/auth/**`, `**/policy/**`, `.githooks/check-no-credentials.js`, `**/*secret*` |
   | published-interface | Alters a published interface | Deep | `docs/spec/**` |
   | data-migration | Migrates data | Deep | `**/migrations/**` |
   | irreversible | Effect cannot be undone | Deep | `.changeset/**`, `tools/nx-plugins/build/executors/publish/**`, `tools/nx-plugins/build/executors/release-reset/**` |

   *Default class per backlog item kind.* The record's value wins over this default.

   | Backlog kind | Default class |
   |---|---|
   | bug | defect-fix |
   | issue | defect-fix |
   | debt | refactor |
   | chore | configuration |
   | investigation | no-code |
   | an item adding a capability | new-behavior |
   | an item whose work is only to add, move or repair tests | test-maintenance |
   | an item that changes a dependency | dependency |
   | an item that changes a published interface or a boundary | boundary-contract |

   *Enforced from: 2026-10-20.* G12 checks only commits authored on or after this date; earlier commits are exempt so that tightening the gate never turns unrelated history red (STRATEGY 10, ratchet).

   *What a range is:* for `check --range <base>..<head>` the change is the branch's own work: the commits in `base..head`, the paths changed from the merge-base to `head`, and the newest commit message in scope that carries a `## Testing record` as its record.

   *Writing the record:* git's default message cleanup deletes lines that start with `#`, so a `## Testing record` typed in the editor is silently dropped. Commit with `-m` or `-F`, or `git commit --cleanup=whitespace`, and G12 reads the committer date, so a rebase after the enforcement date brings older commits into scope.

   *Where the rigor record lives:* the `## Testing record` section in the item's body (`entrypoint/backlog/skill/SKILL.md`, "Testing record"), or in the change description when there is no item.

   *Rigor distribution report (D24):* `node tools/nx-plugins/test/routing/test-routing.mjs distribution` derives the rigor of each recent merged change from git history. Distribution window: 30 merged changes. A change with no testing record in its commit message counts as `unrecorded` and is derived as new behavior at Standard (STRATEGY 6.6).

   *Authorship mode per class and rigor:*

   | Class | None | Light | Standard | Deep |
   |---|---|---|---|---|
   | new-behavior | n/a | implementer may author | separated | separated, required |
   | defect-fix | n/a | implementer may author | separated | separated, required |
   | refactor | n/a | no new tests | separated if tests are touched | separated, required |
   | configuration, dependency | n/a | implementer may author | separated | separated, required |
   | boundary-contract | n/a | n/a | separated | separated, required |
   | test-maintenance | n/a | n/a | the editor is never the confirmer | the editor is never the confirmer |
   | no-code | none | n/a | n/a | n/a |

   9a. **Values the strategy leaves undefined.**
   - Review-debt expiry: 14 days (the strategy default).
   - Retention window for the refactor-forced-edit trigger: 90 days.
   - Escape budget per rigor level, as the share of changes of that level with an escaped defect over the trailing 90 days: None 5%, Light 5%, Standard 3%, Deep 0%. These are starting values and are tightened without ceremony.
   - Stage F, demand-driven: one standing review item per group of tests (a package's `test` and `e2e` suites). Signals counted per 30-day period: a change touching the group, a duration over budget, a flake, a skip past its date. Three signals in a period raise the item one priority step; working the item resets the count. Soak runs, repeat-run flake detection, sampled mutation and capped X smoke run on a weekly clock once a scheduler exists; until then each is an obligation with the owner and review date above.
