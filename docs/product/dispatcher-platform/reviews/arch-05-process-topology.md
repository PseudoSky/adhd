# Process-topology-aligned — architectural critique

**Verdict:** It fixes the shape of the wire-skew bug (types) while leaving its actual cause — a memoized connection that never reconnects to a dead subprocess — not just unfixed but structurally multiplied, because every domain concern this taxonomy can't place gets pushed across a process boundary it just made mandatory.

## 1. Improvements — packages to split/merge/add/remove, boundaries to move, what each buys

- **Split `inproc/` — it silently bundles three unrelated domains under one process-affinity label.** `work-store`, `execution-engine`, and `planner` sit together only because they happen to run in the same process today. Capability 8 (structural exclusivity, store-enforced) requires `work-store` to arbitrate claims from `detached/agent-worker` too — i.e. from *outside* this bucket — so "inproc" is already a lie for the one package whose correctness matters most. Give `work-store` its own package, independent of where planner/engine currently execute, named by domain (`work-*`) not by co-location.
- **Add a `runtime:` tag orthogonal to `domain:`, not a topology directory.** This repo already has the exact mechanism this design reinvents badly: `layer:` is explicitly documented as a tag independent of directory (`domain` is the directory, `layer` is a tag — CLAUDE.md §2), because collapsing the two stranded `packages/ai/*` before. This proposal repeats that mistake one level up: it makes runtime placement *the* directory. Tag packages `runtime:inproc|daemon|edge|detached` and enforce "only a contracts package may be imported across a runtime-tag boundary" via `nx` module-boundary rules / `dependency-checks`, exactly as `layer:` boundaries are enforced today. Same wire-skew guarantee, zero forced file moves when topology changes.
- **Add `provider-plugin-*` and `prompt-*` packages — capabilities 3 and 4 have no home.** "Plugins load by name at runtime from config — zero static importers is the designed state" is a stated fact this diagram ignores entirely: there is no plugin bucket. If provider swap/failover logic all gets stuffed into `detached/agent-worker` because that's the only place LLM calls happen, that one package now owns provider routing, prompt composition, content-hashed caching, and failover — a bigger single package than anything in the current three-subsystem repo this rebuild is meant to fix.
- **Split `edge/` into one contract + generated adapters, not three hand-written siblings.** Capability 10 is "a single operation surface served as CLI, MCP, and HTTP" — that means one operation definition with generated mounts, which is a pattern this monorepo already has in production (apigen: schema derivation, live-mount to HTTP/CLI/MCP with zero codegen drift). `edge/cli`, `edge/mcp`, `edge/http` as three peer packages is three independently-written implementations of the same surface — the identical drift risk as the hand-mirrored wire types, just relocated to the edge tier instead of solved.
- **Name where guards live.** Capability 9 needs to read execution evidence (produced in `detached`), evaluate pass/fail, and inject corrections back into the plan (owned in the split-out `work-*`). No bucket in this diagram owns that; as drawn it's free to be implemented per-caller, which is exactly the "policy rendered as advisory prose" failure this rebuild is meant to kill.

## 2. Primary risks and shortcomings

- **Capability 1 (durable plans) is not served.** The known failure — an unlocked, last-writer-wins JSON file with no recomputation path — is a storage-engine problem. Nothing in `inproc/work-store`'s *location* touches locking or recomputability; the topology relabels the box the bug lives in.
- **Capability 5 (cost caps that block, not warn) is not served.** Spend happens in `detached/agent-worker`; the cap ledger, if anywhere, is nearest `inproc/planner`. Blocking a spawn means `daemon/spawn` needs a synchronous, current view of a cap ledger that lives in a different process across the wire boundary this design just made mandatory — or it checks a stale cached number and overruns by up to one full task, reproducing the exact "advisory, not enforced" failure named in the brief.
- **Capability 7 (HITL steering) is not served.** No package owns "session"; nothing here says whether a session lives in `edge`, `daemon`, or `detached`, which is the direct cause of the current bug (planner fires session-less tasks because sessions aren't a concept the planner can see). Relocating packages by process doesn't manufacture that concept.
- **Substitutability is undermined, not helped, for providers.** Provider plugins have no bucket; they get flattened into whichever package touches an LLM call, which is a regression from a pluggable, name-loaded seam to a monolith-by-default.
- **Recoverability is the one factor this design plausibly helps** — a single wire contract does remove one class of parse-time surprise — but only for the shape of messages, not for their delivery: nothing here specifies retry, acknowledgment, or idempotency for writes crossing the new inproc/daemon/detached seams, so the "durable record with no recomputation path" failure can now also arrive as a dropped RPC.

## 3. What fails first — as this grows and runs unattended for long periods

The design converts what could have been in-process function calls (planner → work-store, supervisor → engine) into cross-process calls by definition, because it makes "which process" the organizing axis and then insists nothing spans a boundary. Every plan step's read/write of state now potentially crosses `inproc ↔ daemon ↔ detached`. The already-known failure — "the client memoizes its connection and never reconnects, so a dead subprocess poisons every subsequent cycle" — has exactly one boundary to occur on today; this topology creates at least three (daemon↔detached spawn/health, daemon↔inproc state sync, edge↔inproc/daemon dispatch) and provides no lifecycle contract (healthCheck/restart/reconnect) for any of them — only a shared type package, which guarantees payload shape, not connection liveness. Unattended, long-running operation is precisely where connection rot compounds; this design multiplies the surface for the one bug already proven to poison every subsequent cycle without adding anything to prevent it.

## 4. Topology as a boundary

Coupling package layout to process topology means every topology change — merging daemon supervision back into a single-user process, or splitting `agent-worker` further — forces a physical file move across every consumer's import path, which this repo's own convention (stable `<domain>-<tier>-<name>` paths, publish breaks on import-specifier divergence) treats as a real cost, not a cosmetic one. The wire-skew guarantee it buys is real but cheaper to get orthogonally: a `runtime:` tag plus an nx boundary rule forbidding cross-tag imports except through a contracts package gets the identical "exactly one wire type" guarantee without ever forcing a move when topology — which this brief itself calls an operational decision that changes — actually changes.

## 5. The single worst thing about this design

It solves wire-skew (a types problem) by making process crossings structurally mandatory, but supplies no connection-lifecycle contract for those crossings — so it doesn't fix the named failure (dead subprocess, memoized connection, no reconnect, poisoned next cycle), it manufactures more places for exactly that failure to recur, unattended, at the worst possible time to discover it.
